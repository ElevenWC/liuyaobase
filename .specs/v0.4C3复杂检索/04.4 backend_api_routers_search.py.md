# 文件规划：backend/api/routers/search.py

## 1. 基本信息
- **所属模块**：api/routers/
- **优先级**：P0
- **依赖文件**：`backend/services/search_service.py`、`backend/services/export_service.py`、`backend/schemas/search.py`
- **被依赖文件**：`backend/api/main.py`

## 2. 核心职责
C3 检索 API 路由——复杂检索/推荐方案/导出。

## 3. 对外接口
```python
router = APIRouter(prefix="/api/search", tags=["检索"])

@router.post("")              # 执行复杂检索（核心接口）
@router.get("/schemes")       # 获取推荐方案列表
@router.post("/export")       # 导出检索结果（csv/json）
```

## 4. 内部逻辑要点
- `/search` POST：接收 SearchRequest → 校验 → 调 search_service.execute_search() → 返回 SearchResponse
- `/schemes` GET：返回预设检索模板（如"动爻带干禄""世爻是驿马"等）
- `/export` POST：接收 SearchRequest + format → 调 export_service → 返回文件

## 5. 测试要点
- POST /api/search 正常条件返回结果
- POST /api/search 空条件返回全部（分页）
- GET /api/search/schemes 返回数组

### 用户测试 👤
浏览器访问 `http://localhost:8001/docs`，在 Swagger 页面测试 POST /api/search。输入：
```json
{"conditions":[{"id":"c1","field":"ben_liuqin","operator":"equals","value":"妻财","scope":"ben_gua"}],"logic":[{"type":"condition","id":"c1"}],"pagination":{"page":1,"page_size":50}}
```

## 6. 潜在陷阱与风险
- [检索超时] 复杂条件 + 大数据量 → SQL 执行时间长。设置合理的 timeout（10s），超时返回提示。

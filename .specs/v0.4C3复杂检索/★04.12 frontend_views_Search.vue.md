# 文件规划：frontend/src/views/Search.vue 🟡

## 1. 基本信息
- **所属模块**：frontend/views/
- **优先级**：P0
- **依赖文件**：`useSearchStore.js`、全部 Search 子组件
- **被依赖文件**：`frontend/src/router/index.js`

## 2. 核心职责
C3 检索主页面——组合 ConditionBuilder、FieldLibrary、ResultList、CompareMode、RecommendedSchemes 等组件。

## 3. 页面布局
```
┌────────────────────────────────────────────────┐
│  检索表达式预览：本卦妻财爻 AND 动爻             │
├──────────┬─────────────────────────────────────┤
│ 字段库   │  条件构建区                          │
│ (可折叠) │  ┌─ 同一爻条件组 ──────────┐       │
│          │  │ 来源:本卦 六亲=妻财     │       │
│ - 时间   │  └──────────────────────┘       │
│ - 卦类   │                                   │
│ - 爻属性 │  + 添加条件  + 添加条件组           │
│ - 关系   │                                   │
│ - 神煞   │  [AND] [OR] [NOT] [( )]           │
│ - 数目   │                                   │
├──────────┴─────────────────────────────────────┤
│  推荐方案: [动爻带干禄] [世爻是驿马] ...        │
├────────────────────────────────────────────────┤
│  结果列表 (ResultList)                         │
│  ┌──────────────────────────────────────┐     │
│  │ 序号 │ 时间 │ 事由 │ 本卦 │ 之卦 │ 标签│     │
│  │ ...                                   │     │
│  └──────────────────────────────────────┘     │
│  共 N 条  < 1 2 3 ... >                       │
└────────────────────────────────────────────────┘
```

## 4. 内部逻辑要点
- 左侧字段库默认展开，可折叠
- 中部条件构建区可无限滚动添加条件
- 底部结果列表在每次 `executeSearch()` 后更新
- 批量打标签：多选结果→弹出标签选择器→调 API 批量关联
- 检索表达式预览：实时展示当前条件的自然语言描述

## 5. 测试要点
- 添加条件→点搜索→结果列表更新
- 切换字段库分类不影响条件构建区
- 清空条件→点搜索→返回全部卦例

### 用户测试 👤
浏览器中打开检索页面，按以下步骤测试：
1. 选择"本卦六亲"="妻财"→搜索→看结果中每个卦例本卦都有妻财爻
2. 添加关系条件"世爻克妻财爻"→搜索→验证
3. 切换推荐方案→条件自动填充→搜索

## 6. 潜在陷阱与风险
- [页面性能] 条件很多时重新渲染慢 → 条件构建区使用 `v-memo` 或组件级懒加载。
- [浏览历史] 用户点搜索结果跳转到 C1 详情→返回→检索条件丢失？用 Pinia store 保持状态，不要用组件 local state。

## 4. 内部逻辑要点

### 4.1 条件 → SQL 转换规则

| 条件类型 | SQL 生成方式 | 示例 |
|---------|------------|------|
| 普通字段（=） | `field = :value` | `y.ben_liuqin = '妻财'` |
| 普通字段（IN） | `field IN (:values)` | `y.ben_liuqin IN ('妻财','官鬼')` |
| 神煞字段（是） | `FIND_IN_SET(y.yao_position, s.ben_is_ganlu) > 0` | |
| 神煞字段（带） | `FIND_IN_SET(y.yao_position, s.ben_dai_ganlu) > 0` | |
| 关系字段（生克） | `check_sheng(d1, d2) = TRUE` | |
| 关系字段（合冲半合） | `check_he(d1, d2) = TRUE` | |
| 关系字段（三合） | `check_sanhe(d1, d2, d3) = '火'` | |
| 关系字段（生旺墓绝） | `check_shengwang(d1, d2, '长生') = TRUE` | |
| 卦类字段 | `g.ben_palace = '离宫'` | JOIN guali_gua |
| 时间字段 | `t.day_zhi = '子'` | JOIN guali_time |
| 数目判断 | `SELECT COUNT(*) ... HAVING COUNT(*) > N` | 子查询 |

### 4.2 动态 JOIN 策略
- 只要涉及爻类字段 → JOIN guali_yao
- 涉及神煞 → JOIN guali_shensha
- 涉及卦类 → JOIN guali_gua
- 涉及时间 → JOIN guali_time
- 优化：同一次检索中相同的 JOIN 只做一次

### 4.3 SQL 安全性
- **禁止字符串拼接用户输入**：全部值使用参数化查询（`:value`）
- 字段名/运算符来自前端 → 用白名单校验
- 逻辑链深嵌套保护：最多 5 层括号

## 7. 潜在陷阱与风险

- [FIND_IN_SET 性能] `FIND_IN_SET(yao_position, '1,3,5')` 无法走索引 → 当数据量变大时可能慢。先通过 is_dong/ben_liuqin 等索引字段缩窄范围，再 FIND_IN_SET。
- [动态 JOIN 遗漏] 条件中引用了 guali_shensha 表但未 JOIN → SQL 执行报错。测试时覆盖所有字段类型。
- [条件组引用] 关系字段引用条件组的结果（如"条件组A的爻克条件组B的爻"）→ 需要子查询或 CTE，这比较难。先做简单的对象引用（世爻/妻财爻等），条件组引用稍后实现。
- [逻辑链解析] 前端发来的 logic 链包含括号嵌套 → 后端解析时需正确处理优先级。用栈或递归下降解析。

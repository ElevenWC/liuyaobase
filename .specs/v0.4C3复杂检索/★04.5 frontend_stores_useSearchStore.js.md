# 文件规划：frontend/src/stores/useSearchStore.js 🟡

## 1. 基本信息
- **所属模块**：frontend/stores/
- **优先级**：P0
- **依赖文件**：`pinia`、`frontend/src/api/index.js`
- **被依赖文件**：全部 Search 组件

## 2. 核心职责
C3 检索专属 Pinia store——条件列表、逻辑链、结果集、分页、加载状态、推荐方案。

## 3. 对外接口

```javascript
export const useSearchStore = defineStore('search', () => {
  const conditions = ref([])          // 条件列表
  const logicChain = ref([])          // 逻辑链
  const results = ref([])             // 检索结果
  const pagination = ref({page:1, pageSize:50, total:0})
  const loading = ref(false)
  const schemes = ref([])             // 推荐方案

  const expressionPreview = computed(() => buildExpression(conditions, logicChain))

  async function executeSearch() { ... }
  function addCondition(type) { ... }
  function removeCondition(id) { ... }
  function updateCondition(id, patch) { ... }
  function addLogicItem(item) { ... }
  async function loadSchemes() { ... }
  function applyScheme(scheme) { ... }

  return { conditions, logicChain, results, pagination, loading,
           expressionPreview, executeSearch, addCondition, ... }
})
```

## 4. 内部逻辑要点
- `expressionPreview`：将 conditions + logicChain 转为人类可读的检索表达式字符串（如"本卦妻财爻 AND 动爻"）
- `executeSearch()`：将 conditions + logicChain 序列化为 SearchRequest → POST /api/search → 填充 results
- `applyScheme(scheme)`：清空当前条件 → 载入推荐方案预设的条件和逻辑链
- 推荐方案存储：当前从后端 GET /api/search/schemes 获取（以后可改为 localStorage）

## 5. 测试要点
- 添加条件→expressionPreview 实时更新
- executeSearch 返回空结果时 results=[]（不报错）
- 切换页码→重新请求

## 6. 潜在陷阱与风险
- [条件 ID 冲突] 删除条件后新增可能 ID 重复 → 用自增计数器生成唯一 ID。
- [逻辑链不完整] conditions 有数据但 logicChain 为空 → executeSearch 应报错或默认 AND 连接。

# 文件规划：backend/db/stored_functions/（8 个 .sql 文件）🔴

> 🔴 核心文件组：C3 复杂检索的运行时判断基础。函数逻辑错误 → 检索结果全部出错，且难以排查。

## 1. 基本信息
- **所属模块**：基础设施（db/stored_functions/）
- **优先级**：P0（必须）— C3 复杂检索直接调用这些函数
- **依赖文件**：无（纯 MySQL 函数，不依赖项目代码）
- **被依赖文件**：`backend/db/init_db.py`（注册函数）、`backend/services/search_service.py`（C3 检索 SQL 生成）

## 2. 核心职责
实现地支关系判断的 MySQL 存储函数，供 C3 复杂检索的 SQL 查询直接调用。开发流程：先在 Python 层实现并测试 → 验证通过后移植为 MySQL 函数。

## 3. 文件清单与接口

| 文件 | 函数签名 | 返回 | 说明 |
|------|---------|:--:|------|
| `check_sheng.sql` | `check_sheng(dizhi_a VARCHAR(2), dizhi_b VARCHAR(2))` | BOOLEAN | A生B？有顺序 |
| `check_ke.sql` | `check_ke(dizhi_a VARCHAR(2), dizhi_b VARCHAR(2))` | BOOLEAN | A克B？有顺序 |
| `check_he.sql` | `check_he(dizhi_a VARCHAR(2), dizhi_b VARCHAR(2))` | BOOLEAN | 相合？6组，无顺序 |
| `check_chong.sql` | `check_chong(dizhi_a VARCHAR(2), dizhi_b VARCHAR(2))` | BOOLEAN | 相冲？6组，无顺序 |
| `check_banhe.sql` | `check_banhe(dizhi_a VARCHAR(2), dizhi_b VARCHAR(2))` | BOOLEAN | 半合？8组，无顺序 |
| `check_sanhe.sql` | `check_sanhe(dizhi_a VARCHAR(2), dizhi_b VARCHAR(2), dizhi_c VARCHAR(2))` | VARCHAR(2) | 三合局？返回五行字符（水/木/火/金），不形成返回 '' |
| `check_shengwang.sql` | `check_shengwang(dizhi VARCHAR(2), target VARCHAR(2), sw_type VARCHAR(4))` | BOOLEAN | 生旺墓绝？sw_type: 长生/帝旺/墓/绝 |
| `check_bagong_relation.sql` | `check_bagong_relation(ben_code VARCHAR(6), zhi_code VARCHAR(6))` | VARCHAR(4) | 八宫变化类型（一世~归魂），不匹配返回 '' |

## 4. 内部逻辑要点

### 4.1 check_sheng / check_ke
- 地支 → 五行映射：子水、丑土、寅木、卯木、辰土、巳火、午火、未土、申金、酉金、戌土、亥水
- 相生链：木→火→土→金→水→木
- 相克链：木→土→水→火→金→木
- MySQL 实现：用 `CASE WHEN` 或嵌套 `IF` 判断五行 → 查生克表

### 4.2 check_he / check_chong
- 六合 6 组：子丑、寅亥、卯戌、辰酉、巳申、午未
- 六冲 6 组：子午、丑未、寅申、卯酉、辰戌、巳亥
- 无顺序 → `check_he('子','丑')` = `check_he('丑','子')` = TRUE
- MySQL 实现：用 `IF` 判断 (a,b) 或 (b,a) 是否在合/冲列表中

### 4.3 check_banhe
- 8 组半合对：申子、子辰、亥卯、卯未、寅午、午戌、巳酉、酉丑
- 无顺序，判断逻辑同 check_he

### 4.4 check_sanhe
- 4 个三合局：申子辰(水)、亥卯未(木)、寅午戌(火)、巳酉丑(金)
- 返回 VARCHAR(2) 而非 BOOLEAN → 支持指定局查询（`= '水'`）和不限局查询（`!= ''`）
- 三个地支无顺序 → 需排序后或全排列判断

### 4.5 check_shengwang
- 生旺墓绝对照表（见 .B核心算法.md §9.5）
- sw_type 参数区分四种判断：长生 → 查长生列，帝旺 → 查帝旺列，墓 → 查墓列，绝 → 查绝列
- 地支先映射为五行，再查表

### 4.6 check_bagong_relation
- 从 ben_code 出发，依次施加七种变化（一世~归魂），每步检查是否等于 zhi_code
- 上爻（第 6 位）永不参与变化
- MySQL 实现：用 `SUBSTRING` 和 `CONCAT` 逐位翻转

## 5. 输入输出示例

```sql
SELECT check_sheng('子', '寅');   -- 1（水生木）
SELECT check_ke('子', '午');      -- 0（子克午？水克火=TRUE，但这是相冲不是相克。实际：水克火→子克巳午→返回1... 等一下，子水克午火，应该是1）
-- 修正：子水克午火 → TRUE
SELECT check_he('子', '丑');      -- 1（子丑合）
SELECT check_chong('子', '午');   -- 1（子午冲）
SELECT check_banhe('申', '子');   -- 1（申子半合水局）
SELECT check_sanhe('申','子','辰'); -- '水'
SELECT check_sanhe('申','子','丑'); -- ''（不形成三合局）
SELECT check_shengwang('寅', '亥', '长生'); -- 1（木长生在亥）
SELECT check_bagong_relation('111111', '011111'); -- '一世'（乾为天→天风姤）
```

## 6. 测试要点

### AI 自测
- 每个函数至少 10 个用例，先 Python 后 MySQL

### 用户测试 👤（复制命令到终端执行）

存储函数的测试包含在 00.5 的测试第 7 步中。以下是更详细的逐个函数验证命令：

```bash
# 1. 相生：子水生寅木 → 1
mysql -u root -p020508 liuyao -e "SELECT check_sheng('子', '寅') AS 子生寅;"

# 2. 相克：子水克午火 → 1
mysql -u root -p020508 liuyao -e "SELECT check_ke('子', '午') AS 子克午;"

# 3. 六合：子丑合 → 1，子寅不合 → 0
mysql -u root -p020508 liuyao -e "SELECT check_he('子', '丑') AS 子丑合, check_he('子', '寅') AS 子寅合;"

# 4. 六冲：子午冲 → 1
mysql -u root -p020508 liuyao -e "SELECT check_chong('子', '午') AS 子午冲;"

# 5. 半合：申子半合水局 → 1
mysql -u root -p020508 liuyao -e "SELECT check_banhe('申', '子') AS 申子半合, check_banhe('子', '申') AS 子申半合;"
# 预期：申子半合=1，子申半合=1（无顺序）

# 6. 三合：申子辰 → '水'，亥卯未 → '木'，寅午戌 → '火'，巳酉丑 → '金'
mysql -u root -p020508 liuyao -e "SELECT check_sanhe('申','子','辰') AS 水局, check_sanhe('亥','卯','未') AS 木局, check_sanhe('寅','午','戌') AS 火局, check_sanhe('巳','酉','丑') AS 金局, check_sanhe('子','丑','寅') AS 不成局;"
# 预期：水局=水，木局=木，火局=火，金局=金，不成局=''（空）

# 7. 生旺墓绝：寅木长生在亥 → 1
mysql -u root -p020508 liuyao -e "SELECT check_shengwang('寅', '亥', '长生') AS 寅长生在亥, check_shengwang('寅', '卯', '帝旺') AS 寅帝旺在卯;"

# 8. 八宫变化：乾为天→天风姤（一世变）→ '一世'
mysql -u root -p020508 liuyao -e "SELECT check_bagong_relation('111111', '011111') AS 一世变, check_bagong_relation('111111', '111111') AS 相同卦;"
# 预期：一世变=一世，相同卦=''（空）
```

> 注意：`check_sanhe` 返回的是单个中文字（'水'/'木'/'火'/'金'/''），不是 '水局' 也不是 NULL。

## 7. 潜在陷阱与风险

### 规则类陷阱
- [五行映射错误] 土的地支 4 个（丑辰未戌），生克表容易遗漏。check_sheng/check_ke 必须覆盖全部 12 地支。
- [生克方向] check_sheng('子', '寅') 是水生木=TRUE，但 check_sheng('寅', '子') 是木生水=FALSE。函数签名中第一个参数是主动方。
- [半合 vs 六合] 半合和六合是不同的概念——申子是半合，子丑是六合。两个函数不能混淆。
- [三合返回空串 vs NULL] MySQL 中 `''` 和 `NULL` 行为不同。`WHERE check_sanhe(...) != ''` 不会匹配 NULL。必须确保不形成三合时返回 `''` 而非 `NULL`。
- [check_bagong_relation 上爻不变] 归魂变翻转前 3 位（初二三爻），上爻（第 6 位）从头到尾不动。如果误把第 6 位也翻了 → 归魂变结果全错。

### MySQL 实现类陷阱
- [SUBSTRING 索引] MySQL 的 `SUBSTRING(str, pos, len)` 中 pos 从 1 开始，不是 0。翻转初爻要用 `SUBSTRING(code, 1, 1)`。
- [函数返回值类型] `RETURNS BOOLEAN` 在 MySQL 中实际返回 INT(1)，PHP/Java 可能读成整数 → 在 SQL 中用 `= TRUE` 判断，不做隐式转换假设。
- [函数注册失败] 如果 init_db.py 执行 SQL 文件时遇到语法错误 → 静默跳过，后续检索报错。规避：注册后立即执行测试查询，失败则抛出异常。

### 测试盲区
- 只测正常地支组合，没测无效输入（如 `check_sheng('猫', '狗')`）→ MySQL 函数应有基本的输入校验或默认返回 FALSE。
- check_sanhe 三个地支完全相同（如 '子','子','子'）→ 应返回 ''。
- check_bagong_relation 两个相同代码 → 应返回 ''（不是任何变化关系）。

# 文件规划：backend/config.py

## 1. 基本信息
- **所属模块**：基础设施
- **优先级**：P0（必须）— 所有后端模块启动依赖此文件
- **依赖文件**：无（纯配置文件，不导入项目内其他模块）
- **被依赖文件**：`backend/db/connection.py`、`backend/main.py`、`backend/services/stock_data_service.py`、以及任何需要读取配置的模块

## 2. 核心职责
集中管理所有可配置常量——数据库连接参数、服务端口、AKShare 限流参数，避免硬编码分散在各模块中。

## 3. 对外接口
配置项以模块级常量形式暴露，例如：
```python
# 数据库
DATABASE_URL: str          # "mysql+pymysql://root:020508@localhost:3306/liuyao"
DATABASE_HOST: str         # "localhost"
DATABASE_PORT: int         # 3306
DATABASE_USER: str         # "root"
DATABASE_PASSWORD: str     # "020508"
DATABASE_NAME: str         # "liuyao"

# 服务
SERVER_HOST: str           # "0.0.0.0"
SERVER_PORT: int           # 8001（8000已被占用）

# AKShare
AKSHARE_RATE_LIMIT: float  # 0.5（QPS，即2秒1次）
AKSHARE_TIMEOUT: int       # 30（请求超时秒数）
```

## 4. 内部逻辑要点
- 所有值为常量，无函数逻辑
- 可用 `os.environ.get()` 支持环境变量覆盖（便于不同环境切换）
- 数据库密码等敏感信息优先从环境变量读取，本地开发用默认值

## 5. 输入输出示例
无——配置文件不接收运行时输入。启动时被各模块 import，读取常量。

## 6. 测试要点

### AI 自测
- 启动后端不报错，能读配置连接数据库

### 用户测试 👤
以下命令在 VS Code 终端中执行：

**1. 先确认 MySQL 服务在运行**：
打开一个新的终端窗口，输入：
```bash
mysql -u root -p020508 -e "SHOW DATABASES;"
```
应该能看到 `liuyao` 数据库在列表中。

**2. 启动后端**：
```bash
cd d:/Code/liuyao/liuyaobase
uvicorn backend.main:app --reload --port 8001
```
看到 `Uvicorn running on http://0.0.0.0:8001` 就说明配置正确，启动成功。按 `Ctrl+C` 可停止。

## 7. 潜在陷阱与风险
- [敏感信息泄露] 数据库密码写在代码中 → 提交到 GitHub 后公开可见。规避：提供 `config.example.py` 模板（密码用占位符），真实 `config.py` 加入 `.gitignore`。**上传 GitHub 前将敏感信息脱敏处理。**
- [端口冲突] 默认端口被占用 → 应用启动失败。规避：`SERVER_PORT` 设为非标准端口（如 8001），并在 README 中注明。
- [环境差异] 本地和服务器数据库参数不同 → 每次部署手动改代码。规避：用环境变量读取，代码中只写默认值。

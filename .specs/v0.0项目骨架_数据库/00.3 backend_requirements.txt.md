# 文件规划：backend/requirements.txt

## 1. 基本信息
- **所属模块**：基础设施
- **优先级**：P0（必须）— 所有后端模块的依赖声明
- **依赖文件**：无
- **被依赖文件**：全部后端模块（通过 `pip install -r requirements.txt` 安装）

## 2. 核心职责
声明 Python 项目所有依赖包及其版本，确保环境可复现。

## 3. 对外接口
无——这是 Pip 的依赖声明文件，不被代码导入。

## 4. 内部逻辑要点
依赖清单及用途：

| 包名 | 用途 | 涉及模块 |
|------|------|---------|
| `fastapi` | Web 框架 | 全部 API |
| `uvicorn[standard]` | ASGI 服务器 | main.py 启动 |
| `sqlmodel` | ORM（SQLAlchemy + Pydantic） | models/ + crud/ |
| `pymysql` | MySQL 数据库驱动 | db/connection.py |
| `lunar-python` | 农历/干支转换 | core/time_converter.py |
| `akshare` | A 股数据接口 | services/stock_data_service.py |
| `python-dotenv` | .env 环境变量加载 | config.py |
| `pytest` | 测试框架 | tests/ |
| `httpx` | HTTP 测试客户端（FastAPI TestClient 依赖） | tests/ |

## 6. 测试要点

### AI 自测
- `pip install -r requirements.txt` 无报错

### 用户测试 👤
以下命令在 VS Code 终端中执行：

**1. 创建虚拟环境（首次）**：
```bash
cd d:/Code/liuyao/liuyaobase
python -m venv venv
```

**2. 激活虚拟环境**：
```bash
venv\Scripts\activate
```
看到命令行前面出现 `(venv)` 说明激活成功。

**3. 安装依赖**：
```bash
pip install -r backend/requirements.txt
```
等待安装完成，最后应显示 `Successfully installed ...` 没有红色报错就行。

## 7. 潜在陷阱与风险
- [版本锁定过死] 固定 `==` 版本号 → 后续环境可能无法安装。规避：使用 `>=` 最小版本约束，仅在确有必要时报出具体版本。
- [AKShare 版本变化] AKShare 接口不稳定，版本升级可能改变 API 返回格式 → 在开发阶段锁定一个已知可用的版本范围，后续升级时重点测试 C4 模块。
- [pymysql vs mysqlclient] pymysql 是纯 Python 实现，性能不如 mysqlclient 但无需编译 → 对当前项目数据量足够，选 pymysql。

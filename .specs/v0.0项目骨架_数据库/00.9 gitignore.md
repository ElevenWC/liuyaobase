# 文件规划：.gitignore

## 1. 基本信息
- **所属模块**：基础设施
- **优先级**：P0（必须）
- **依赖文件**：无
- **被依赖文件**：全部（Git 根据此文件决定哪些文件不跟踪）

## 2. 核心职责
告诉 Git 忽略不需要版本控制的文件——编译产物、依赖包、环境配置、用户文件、日志等。

## 3. 对外接口
无——这是 Git 配置文件，不被代码调用。

## 4. 内部逻辑要点
本项目需排除的内容：

| 类别 | 规则 | 原因 |
|------|------|------|
| Python 缓存 | `__pycache__/`、`*.pyc` | 编译产物 |
| 虚拟环境 | `venv/`、`.venv/` | 本地环境，不跨机器共享 |
| 环境变量 | `.env` | 含数据库密码等敏感信息 |
| IDE 配置 | `.idea/`、`.vscode/`、`*.swp` | 个人编辑器配置 |
| 日志 | `*.log`、`logs/` | 运行时日志 |
| 数据库文件 | `*.db`、`*.sqlite3` | 本地数据库 |
| Node 依赖 | `node_modules/` | npm install 生成，不提交 |
| 构建产物 | `dist/` | 前端构建输出 |
| 测试缓存 | `.pytest_cache/`、`.coverage` | 测试框架产生 |
| 用户文档 | `.user/` | 用户私有参考，不提交 |
| 图片（保留目录） | `images/*` + `!images/.gitkeep` | 上传的图片不提交，但保留目录结构 |
| OS 文件 | `.DS_Store`、`Thumbs.db` | 操作系统自动生成 |

## 5. 输入输出示例
- 在 `.user/` 下新增文件 → `git status` 不显示
- `git add .` → `.user/` 和 `node_modules/` 不会被暂存

## 6. 测试要点

### AI 自测
- `git status` 确认忽略规则生效

### 用户测试 👤（复制命令到终端执行）

在 VS Code 终端中执行：

**1. 检查忽略规则是否生效**：
```bash
cd d:/Code/liuyao/liuyaobase
git status
```
确认输出中**不出现**以下内容：`__pycache__/`、`venv/`、`node_modules/`、`.user/`、`.env`

**2. 确认 images 目录存在但图片被忽略**：
```bash
ls images/
```
应该看到 `.gitkeep` 文件，而 `.jpg` 图片文件不会被 Git 跟踪。

**3. 确认 .user 文件夹被完全忽略**：
```bash
git status --short
```
输出中不应该出现任何 `.user/` 开头的文件。

## 7. 潜在陷阱与风险
- [误忽略源文件] 规则写错了路径 → 关键源文件未提交。规避：`.gitignore` 中添加新规则后，用 `git status` 确认预期文件仍被跟踪。
- [.gitkeep 丢失] `images/*` + `!images/.gitkeep` 的写法依赖于 `.gitkeep` 存在 → 如果 `.gitkeep` 被删除，空 `images/` 目录无法被 Git 跟踪。
- [之前已跟踪的文件被忽略] 如果文件之前已 `git add`，后加入 `.gitignore` 不会自动停止跟踪 → 需 `git rm --cached` 移除跟踪。

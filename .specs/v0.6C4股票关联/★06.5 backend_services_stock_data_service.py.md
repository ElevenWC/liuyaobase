## 1. 基本信息
- **所属模块**：services/
- **优先级**：P1
- **依赖文件**：`backend/crud/stock_info.py`、`backend/crud/stock_day_kline.py`、`backend/crud/stock_minute_kline.py`、`akshare`

## 2. 核心职责
AKShare 数据获取 + 增量更新 + 限流控制。用户添加标的时首次拉取历史数据，之后手动触发增量更新。

## 4. 内部逻辑要点

### 数据获取流程
1. 用户搜索股票名/代码 → AKShare 搜索
2. 用户选择标的 + 日期范围 → 确认添加
3. 后端调 AKShare 获取历史日K → INSERT IGNORE 入库
4. 调 AKShare 获取分钟K（分月循环，单月超 3 个月会失败） → 入库
5. 增量更新：查 MAX(trade_date) → 从该日后一天拉到今天

### 限流
- AKShare 限流 0.5 QPS（2 秒 1 次）
- 批量获取分钟K时，每次请求间 `await asyncio.sleep(2)`
- 限流独立于股（不同股票不共享限流配额？不，AKShare 是全局限流）

### 增量更新逻辑

async def update_stock_data(stock_id, session):

## 6. 潜在陷阱与风险
- [AKShare 接口不稳定] 股票日K接口之前就经常连不上→加重试机制（最多 3 次，间隔 5 秒）。
- [分钟K分月拉取] 单次请求最多 3 个月的分钟K→需要循环拉取，按月份拆分 start_date/end_date。
- [数据源备用] 如果网易/东方财富源都不可用→提示用户"数据源暂不可用，请稍后再试"，不要静默失败。

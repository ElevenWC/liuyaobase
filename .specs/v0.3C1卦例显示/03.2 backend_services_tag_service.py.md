# 文件规划：backend/services/tag_service.py

## 1. 基本信息
- **所属模块**：services/
- **优先级**：P1
- **依赖文件**：`backend/crud/tag.py`
- **被依赖文件**：`backend/api/routers/tags.py`、`backend/services/zhanyan_service.py`

## 2. 核心职责
标签业务逻辑——CRUD + 树形结构组装 + 卦例关联管理。标签为二级结构（parent_id 自引用）。

## 4. 内部逻辑要点
- 树形结构：一级标签 parent_id=NULL，查询所有一级→各自关联的二级
- 删除一级标签前检查是否有二级子标签→有则提示先删子标签或一并删除
- 占验标签互斥逻辑（见 .C1 §8.4）：修改占验时先 DELETE 旧关联再 INSERT 新关联

## 5. 输入输出示例
```python
get_tag_tree(session)
# → [{"id":1, "name":"股票", "children":[{"id":2, "name":"ST生物"}, ...]}, ...]
```

## 6. 测试要点
- 创建二级标签→get_tag_tree 中出现在对应一级标签下
- 删除有子标签的一级标签→应提示或级联删除

## 7. 潜在陷阱与风险
- [循环引用] parent_id 指向自身 → 树形遍历死循环。创建时校验 parent_id != tag_id。
- [占验互斥] 用户选择"应验"→先删除旧的"模糊"/"不验"关联，再插入"应验"。删除和插入应在同一事务。

# 文件规划：backend/services/（C2 复用 core/）

## 1. 基本信息
- **所属模块**：services/
- **优先级**：P1
- **依赖文件**：`backend/core/hugua.py`（B7 互卦）、`backend/core/bagong_bian.py`（B8 八宫变化）、`backend/crud/guali.py`、`backend/crud/guali_gua.py`、`backend/crud/bagong_gua.py`
- **被依赖文件**：`backend/api/routers/bagong.py`、`backend/api/routers/jiegua.py`

## 2. 核心职责
C2 解卦模块不新建独立 service 文件。八宫变化和互卦的计算逻辑已在 v0.1 的 core/ 中实现，API 路由直接调用 core/ 函数 + CRUD 读数据库。

## 3. API 路由层可直接调用的函数

```python
# 来自 core/bagong_bian.py
calc_bagong_bian(code: str) -> list[dict]       # 八宫七变
check_bagong_relation(ben, zhi) -> str           # 判断变化关系

# 来自 core/hugua.py
calc_hugua(code: str) -> str                     # 互卦计算

# 来自 crud/bagong_gua.py
get_by_code(session, code) -> BagongGua           # 代码→卦名/卦宫

# 来自 crud/guali.py + crud/guali_gua.py
# 卦例编号入口：读 guali 获取 ben_code/zhi_code，读 guali_gua 获取卦宫/特殊类型
```

## 4. 内部逻辑要点
- 不需要新建 service 文件 → router 直接调 core + crud
- 如果需要额外组装逻辑（如拼装八宫变化的完整响应）→ 在 router 层做或考虑加一个简单的 `jiegua_service.py`
- 当前设计：C2 足够简单，router 直接调即可

## 5. 测试要点
- 八宫变化 API 返回 7 步变化结果
- 互卦 API 返回互卦代码+名称

## 6. 潜在陷阱与风险
- [功能膨胀时重构] 如果 C2 后续加新功能（网络图谱算法复杂化）→ 再抽一个 `jiegua_service.py`。

# 文件规划：backend/services/precalculate_service.py 🔴

> 🔴 核心文件：预计算调度中心——串联 B1-B6 全部核心算法，将结果分存 4 张 guali_* 表。任何一步的输入/输出搞错 → 该卦例的全部扩展数据错乱。

## 1. 基本信息
- **所属模块**：services/
- **优先级**：P0（必须）
- **依赖文件**：`backend/core/*`（全部算法模块）、`backend/crud/guali.py`（读取卦例基本信息）、`backend/crud/guali_time.py`、`backend/crud/guali_yao.py`、`backend/crud/guali_shensha.py`、`backend/crud/guali_gua.py`、`backend/crud/bagong_gua.py`
- **被依赖文件**：`backend/services/import_service.py`

## 2. 核心职责
**预计算调度中心**：给定卦例 ID，从 guali 主表读取原始数据 → 逐个调用核心算法 → 将计算结果分存到 4 张 guali_* 扩展表。导入时每个卦例调用一次。

## 3. 对外接口

```python
def precalculate(session: Session, guali_id: int):
    """主入口——对指定卦例执行全部预计算并存入扩展表
```

## 4. 内部逻辑要点

### 完整计算流程

```
guali 主表
    │
    ├─→ (1) B1 time_converter.convert_time(zhanwen_time)
    │        → guali_time（1行11字段）
    │
    ├─→ (2) B3 liushen.get_liushen(day_gan)
    │        → 6爻六神列表
    │
    ├─→ (3) 查 static_gua_yao_info（本卦6爻预存数据）
    │        → ben_dizhi, ben_liuqin, ben_tiangan
    │
    ├─→ (4) 查 static_gua_yao_info（之卦6爻预存数据）
    │        → zhi_dizhi, zhi_liuqin, zhi_tiangan
    │
    ├─→ (5) B4 shi_ying（本卦世应 + 之卦世应）
    │
    ├─→ (6) B4 fushen_yimao（6爻易冒伏神）
    │
    ├─→ (7) B4 fushen_zengshan（增删伏神，0~2爻）
    │
    ├─→ (8) B3.5 an_dong（逐爻判断暗动）
    │
    ├─→ (9) 组装 guali_yao（6行×20字段）
    │
    ├─→ (10) B5 shensha.calc_shensha_status()
    │         → guali_shensha（1行37字段）
    │
    └─→ (11) B6 gua_type + 查 bagong_gua
              → guali_gua（1行14字段）
```

### 关键：变爻六亲计算
- 变爻六亲用**本卦卦宫五行** + 变爻地支五行（不是之卦卦宫！）
- 之卦静爻六亲同样用本卦卦宫五行
- 本卦卦宫从 bagong_gua 表查询：`SELECT palace FROM bagong_gua WHERE code=ben_code`

### 组装 guali_yao 的数据来源对照

| 字段组 | 来源 | 说明 |
|--------|------|------|
| yao_position | 1-6 | 固定 |
| liushen | 步骤(2) | 6个值按顺序填入 |
| yimao_* | 步骤(6) | 6爻各有伏神 |
| zengshan_* | 步骤(7) | 仅有的爻位有值，其余为空 |
| ben_* | 步骤(3)+(5) | 本卦纳甲+世应 |
| is_dong | 爻变代码 | ben_code XOR zhi_code 逐位判断 |
| is_an_dong | 步骤(8) | 仅静爻可暗动 |
| zhi_* | 步骤(4)+(5) | 之卦纳甲+世应（6爻共享） |

## 7. 潜在陷阱与风险

- [变爻六亲卦宫搞错] 变爻六亲必须用**本卦卦宫**五行。如果用之卦卦宫 → 变爻六亲全错。这是预计算中最隐蔽的错误——代码自洽、测试数据少时不易发现。
- [步骤顺序] 本卦卦宫需要在步骤(3)之前从 bagong_gua 表查询。如果查询失败（卦代码不在表中）→ 整个预计算失败。bagong_gua 表在 v0.0 已填充，不应缺数据。
- [爻变代码位序] 6位爻变代码从左到右=初爻到上爻。is_dong 判断时 `yao_bian_code[yao_position-1] == '1'`（注意 0-based vs 1-based）。
- [事务] 如果步骤(9)-(11)中某步失败 → 前面已写入的 guali_time/guali_yao 未回滚，数据不一致。建议整个 precalculate() 包装在一个事务中。
- [性能] 每个卦例 11 步计算涉及 6+ 次数据库查询（查 static_* + bagong_gua）→ 批量导入时可能慢。可以考虑缓存 bagong_gua 查询结果（64 行全载入内存）。

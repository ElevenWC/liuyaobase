## 4. 内部逻辑要点

### 4.1 JSON 字段映射
| JSON 字段 | 数据库字段 | 转换规则 |
|---------|----------|---------|
| dIniTime | zhanwen_time | 见 4.2 |
| dTitle | zhanwen_shiyou | 直接映射 |
| dNote | zhanduan | `\n` → 换行 |
| dyaolist | ben_code + yao_bian_code | 见 4.3 |
| — | zhi_code | ben_code XOR yao_bian_code |

### 4.2 占问时间提取
1. 检查 dTitle 中是否含 `MM.DD` 格式的日期
2. 若有 → 提取 dIniTime 的年份 + MM.DD → 只保留年月日，不含时分
3. 若无 → 直接用 dIniTime（也只保留年月日）
4. 若 dTitle 含 `MM.DD-MM.DD` → 不用 dTitle 日期，用 dIniTime

### 4.3 dyaolist 转换
| 符号 | 本卦位 | 爻变位 | 含义 |
|:--:|:--:|:--:|------|
| ′ | 1 | 0 | 静阳爻 |
| ″ | 0 | 0 | 静阴爻 |
| ○ | 1 | 1 | 动阳爻（阳变阴） |
| × | 0 | 1 | 动阴爻（阴变阳） |

解析：`dyaolist = "○,′,″,○,′,′,"` → 去掉尾部逗号 → split(',') → 6个符号 → 生成本卦代码(6位) + 爻变代码(6位)

### 4.4 增量导入
1. 读取 system_config 中的 `last_import_time`
2. 在 JSON 数组中搜索该时间戳对应的位置
3. 只解析该位置**之前**的卦例（文件中前面的卦例时间更晚）
4. 导入完成后更新 `last_import_time` 为本次导入的第一个（时间最晚的）卦例的 dIniTime

### 4.5 重复判断
- 根据 zhanwen_time 判断重复（UNIQUE KEY）
- 重复的跳过，不报错，计入 skipped

### 4.6 导入流程
```
1. 解析 JSON → 过滤增量 → 逐条处理
2. 字段映射 + dyaolist 转换
3. 写入 guali 主表（INSERT）
4. 调用 precalculate_service.precalculate(guali_id)
5. 更新 last_import_time
```

## 7. 潜在陷阱与风险

- [dyaolist 尾部逗号] `"○,′,″,○,′,′,"` 末尾有逗号 → split(',') 会多一个空字符串。处理时先 `strip(',')` 再 split。
- [dTitle 日期提取] 正则匹配 `\d{2}\.\d{2}` 可能误匹配非日期格式（如"12.34"）→ 加入月份范围校验（01-12）。
- [增量导入方向] JSON 文件中第一个卦例时间最晚 → 导入"前面"的卦例（时间更早的）。如果方向搞反 → 重复导入或漏导。
- [zhanwen_time 精度] 只精确到日（不含时分），但 dIniTime 精确到分钟 → 同一天的多个卦例会冲突（UNIQUE KEY）。需确认实际数据中同一天是否有多个卦例。
- [预计算失败回滚] 如果某个卦例的预计算抛异常 → 主表已写入但扩展表缺失，数据不完整。建议：先预计算验证通过再写入主表，或使用事务回滚。

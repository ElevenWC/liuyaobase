# 文件规划：backend/core/bagong_bian.py 🟡

> 🟡 重要：八宫变化是 C2 解卦模块的核心功能，也是 C3 检索 `check_bagong_relation` 的 Python 参考实现基础。

## 1. 基本信息
- **所属模块**：core/
- **优先级**：P1（重要）
- **依赖文件**：`backend/core/enums.py`
- **被依赖文件**：`backend/api/routers/bagong.py`（C2 八宫变化 API）、MySQL 存储函数 `check_bagong_relation`（基于此 Python 实现移植）

## 2. 核心职责
B8 八宫变化：从本卦出发，按固定规则依次施加七种变化（一世变至归魂变），返回每一步的卦代码。上爻永不参与变化。

def check_bagong_relation(ben_code: str, zhi_code: str) -> str:
    """判断之卦是本卦的哪种八宫变化 → "一世"/"二世"/.../"归魂"/"" """

## 4. 内部逻辑要点

### 变化规则（上爻=第6位永不变）

| 步骤 | 操作 | 翻转位（0-based） |
|------|------|:--:|
| 一世变 | 初爻取反 | index 0 |
| 二世变 | 二爻取反（对一世结果） | index 1 |
| 三世变 | 三爻取反 | index 2 |
| 四世变 | 四爻取反 | index 3 |
| 五世变 | 五爻取反 | index 4 |
| 游魂变 | 四爻取反（对五世结果） | index 3 |
| 归魂变 | 前三位全取反 | index 0,1,2 |

### check_bagong_relation 逻辑
从 ben_code 出发，依次施加七种变化，每步检查是否等于 zhi_code。匹配即返回对应类型名，全部不匹配返回空字符串。

## 5. 输入输出示例

```python
calc_bagong_bian("111111")  # 乾为天
# → 一世=011111(天风姤), 二世=001111(天山遁), ...
#    归魂=111101(火天大有)

check_bagong_relation("111111", "011111")  # → "一世"
check_bagong_relation("111111", "111111")  # → ""（相同卦不算变化）
```

## 6. 测试要点
- 乾为天 → 七变结果与八宫卦序表对照
- 上爻永不变：所有结果的第6位(索引5)应与输入相同

## 7. 潜在陷阱与风险
- [上爻永不变] 归魂变翻转前3位（初二三爻），上爻不能动。如果代码循环中翻了索引5 → 归魂变结果错误。
- [check_bagong_relation 顺序] 必须按一世→二世→...→归魂的顺序检查。先匹配到的即为结果（如本卦→一世→之卦，返回"一世"而非继续算到归魂）。
- [翻转后查卦名] 每次翻转后得到新代码 → 需要从 bagong_gua 表查卦名。但 core/ 层不访问数据库 → 调用方自己查。calc_bagong_bian 只返回代码，name 字段由 service 层填充。

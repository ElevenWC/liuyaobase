# 文件规划：backend/core/enums.py

## 1. 基本信息
- **所属模块**：core/
- **优先级**：P0（必须）— 所有核心算法模块的常量和映射表都依赖此文件
- **依赖文件**：无（纯常量定义，不导入任何项目内模块）
- **被依赖文件**：全部 core/*.py、db/init_db.py

## 2. 核心职责
定义六爻系统中所有的枚举常量和映射字典——五行、天干、地支、六亲、六神、八卦、卦宫、宫位类型。每个常量一个直观的英文名，映射字典用于算法中的查表操作。

## 3. 对外接口

```python
# 枚举列表
WU_XING = ["金", "木", "水", "火", "土"]
TIAN_GAN = ["甲", "乙", "丙", "丁", "戊", "己", "庚", "辛", "壬", "癸"]
DI_ZHI = ["子", "丑", "寅", "卯", "辰", "巳", "午", "未", "申", "酉", "戌", "亥"]
LIU_QIN = ["父母", "官鬼", "子孙", "妻财", "兄弟"]
LIU_SHEN = ["青龙", "朱雀", "勾陈", "螣蛇", "白虎", "玄武"]
BA_GUA = ["乾", "兑", "离", "震", "巽", "坎", "艮", "坤"]
GONG_WEI = ["本宫", "一世", "二世", "三世", "四世", "五世", "游魂", "归魂"]

# 映射字典
DIZHI_WUXING = {"子": "水", "丑": "土", "寅": "木", ...}   # 12对
TIANGAN_WUXING = {"甲": "木", "乙": "木", ...}              # 10对
GUA_WUXING = {"乾": "金", "兑": "金", ...}                  # 8对
GUA_TIANGAN = {"震": "庚", "巽": "辛", ...}                 # 6对（乾坤无固定天干）
GUA_CODE = {"乾": "111", "兑": "110", ...}                  # 8对（单卦→3位代码）
```

## 4. 内部逻辑要点
- 所有值为常量，无函数逻辑
- 映射字典是双向的吗？当前只需单向（查五行），不需要反向（五行→地支列表）——但可预留反向映射工具函数
- 代码中所有算法模块 `from backend.core.enums import DIZHI_WUXING, ...`

## 5. 输入输出示例
```python
from backend.core.enums import DIZHI_WUXING, WU_XING
DIZHI_WUXING["子"]  # → "水"
WU_XING             # → ["金", "木", "水", "火", "土"]
```

## 6. 测试要点

### AI 自测
- 所有字典键值对数量正确（地支12、天干10、八卦8 等）
- 没有一个地支/天干/卦名被遗漏

### 用户测试 👤
无需单独测试——后续算法单元测试会暴露任何遗漏或错误。

## 7. 潜在陷阱与风险
- [遗漏] 如果某个核心算法需要新增常量（如三合局的地支组合），但只加到了算法文件里没加到 enums → 其他模块找不到。规避：所有新增常量统一在此文件定义。
- [五行归类错误] 土的地支有 4 个（丑辰未戌），容易漏一个 → 对照 .B核心算法.md §2.6 检查。
- [乾坤天干特殊] 乾坤的天干分季节，无法放入 GUA_TIANGAN 静态字典 → 在注释中标明"乾坤无固定天干，见 najia.py"。

## 1. 基本信息
- **所属模块**：core/

## 2. 核心职责
B1 算法：将公历 datetime 转换为六爻所需的干支时间信息——年柱/月柱/日柱/旬空/节气。同时提供节气日期查询工具函数（C4 使用）。

## 4. 内部逻辑要点
- 使用 `lunar-python` 库，调用链：`Solar.fromDate(dt)` → `solar.getLunar()`
- 年柱：`lunar.getYearGanZhi()`
- 月柱：`lunar.getMonthGanZhi()`
- 日柱：`lunar.getDayGanZhi()`
- 旬空：`lunar.getDayXunKong()` — 返回两个地支如"戌亥"
- 日干 = 日柱[0]，日支 = 日柱[1]（字符串切片）
- **不需要时柱**（只精确到日）
- **节气当日即变月**：lunar-python 应已正确处理，但需验证

## 5. 输入输出示例

正常输入：
```python
convert_time(datetime(2026, 3, 25))
# → day_pillar="甲午", day_gan="甲", day_zhi="午", xun_kong="辰巳"
```

边界输入：
```python
convert_time(datetime(2026, 2, 4))  # 立春当天
# → month_zhi 应为 "寅"（立春当日即变寅月）
```

## 7. 潜在陷阱与风险

- [lunar-python 版本差异] 不同版本的干支计算可能有微调 → 固定版本号，用同一组日期验证。
- [旬空返回值格式] `getDayXunKong()` 返回格式需确认——是 "戌亥" 还是 ("戌", "亥") → 按字符串处理，分割时做兼容。
- [节气日期 C4 依赖] `get_jieqi_dates` 是 C4 农历月聚合的基础。如果节气日期算错 → 月K 全部对不上。需要和 C4 联调时重点验证。
- [夏至/冬至判断] 后续 najia.py（乾坤天干）和 shensha.py 需要知道当前在夏至前还是后 → 此函数不直接判断，但 can 输出 jieqi 字段供调用方自行判断。
- [时区] 所有时间按本地时间处理，不考虑 UTC。如果数据源带时区 → 先转本地时间再传。

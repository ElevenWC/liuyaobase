  "visibility": false

| 字段 | 是否需要 | 说明 |

| `id` | ❌ 不需要 | 原JSON中的id，不用 |

## 二、关键转换算法

### 2.1 占问时间字段处理

**规则**：
- 如果占问事由（`dTitle`）中包含 `MM.DD` 形式的日期，则只取年份
- 如果没有，则使用 `dIniTime` 作为完整占问时间

**示例**：
```
dTitle = "橡胶主连02.27夜盘开盘走势"
包含 "02.27" → 占问时间取年份 + "02.27"
即 "2026-02-27"

dTitle = "今天大盘走势"
不包含日期 → 占问时间 = dIniTime = "2026-02-27 14:49:00"
```

**疑问 Q1**：
- "只取年份"是指什么？是只取年份部分（如"2026"），还是年份+MM.DD（如"2026-02-27"）？
- 占问事由中的日期格式是什么样的？固定是 `MM.DD` 吗？还是可能有其他格式？

【答】Q1：是的,若占问事由中存在MM.DD的日期形式,则只取dIniTime中的年份,如2026
占问事由中的日期格式一定是MM.DD的,且只有这一个,要是MM.DD-MM.DD的格式,也是取dIniTime作为占问时间

### 2.2 dyaolist 字段转换

**四种爻符号**：
| 符号 | 含义 | 说明 |
|------|------|------|
| `′` | 静阳爻 | 不动的阳爻 |
| `″` | 静阴爻 | 不动的阴爻 |
| `○` | 动阳爻 | 阳变阴 |
| `×` | 动阴爻 | 阴变阳 |

**示例**：
```
dyaolist = "○,′,″,○,′,′,"
```

**转换算法**：

**第一遍：生成本卦代码**
- `′` → `1`
- `○` → `1`
- `″` → `0`
- `×` → `0`

```
○,′,″,○,′,′,
↓ ↓ ↓ ↓ ↓ ↓
1,1,0,1,1,1
本卦代码 = 110111
```

**第二遍：生成爻变代码**
- `○` → `1`
- `×` → `1`
- `′` → `0`
- `″` → `0`

```
○,′,″,○,′,′,
↓ ↓ ↓ ↓ ↓ ↓
1,0,0,1,0,0
爻变代码 = 100100
```

**第三遍：计算之卦代码**
```
之卦代码 = 本卦代码 XOR 爻变代码
110111 XOR 100100 = 010011
```

## 四、增量导入机制

### 4.1 需求说明

用户要求：
> 每次导入包含所有卦例的json文件后，都记录最后一个卦例的占问时间。下次再导入时，直接检索这个日期，从这个卦例的前一个卦开始读取。

### 4.2 实现方案

**方案A：数据库记录最后导入时间**

1. 创建一个系统配置表，记录最后导入的占问时间
2. 每次导入时：
   - 读取配置表中的最后时间
   - 只导入时间比最后时间新的卦例
   - 导入完成后，更新最后时间

**方案B：JSON文件顺序假设**

1. 假设JSON文件中卦例是按时间顺序排列的
2. 记录最后导入卦例的唯一标识（如占问时间+占问事由的组合哈希）
3. 下次导入时，找到该标识位置，从其后开始读取

**疑问 Q2**：
- JSON文件中卦例的顺序是否固定？是否一定是按时间排列的？
- 如果有多个JSON文件，如何处理？
- "最后一个卦例（文件中第一个卦例）"这个描述有点矛盾，请确认：是文件中第一个还是最后一个？

【答】Q2：
- 是的,卦例顺序一定按照时间排序
- 不会的,每次只有一个json文件
- 就是在时间上看这是最晚的一个卦例,但是在文件中它是处于第一个{}括号中的

## 五、实现流程

### 5.1 导入流程

```
1. 读取JSON文件
2. 解析所有卦例（每个{}为一个卦例）
3. 获取上次导入的最后时间
4. 过滤：只保留时间 > 最后时间的卦例
5. 对每条卦例：
   a. 解析dTitle → 占问事由
   b. 解析dNote → 占断（转换\n为换行）
   c. 解析dIniTime → 占问时间（或根据dTitle中的日期）
   d. 解析dyaolist → 本卦代码 + 爻变代码
6. 存入数据库
7. 更新最后导入时间
```

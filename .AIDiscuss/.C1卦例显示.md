## 一、模块概述

### 1.1 模块定位

卦例显示模块是系统的**基础模块**，为其他模块提供数据支撑：
- 为 C2 八宫变化解卦 提供卦例数据
- 为 C3 复杂检索 提供检索对象
- 为 C4 股票关联 提供卦例关联

### 1.2 核心功能

| 功能 | 说明 | 优先级 |
|-----|------|-------|
| JSON导入 | 从JSON文件批量导入卦例 | P0 |
| 手动导入 | 手动输入单个卦例 | P1 |
| 卦例列表 | 左侧卡片列表展示 | P0 |
| 卦例详情 | 右侧展示完整信息 | P0 |
| 快捷编辑 | 双击直接编辑 | P1 |
| 卦例删除 | 单个/批量删除 | P1 |
| 标签管理 | 为卦例打标签 | P1 |

### 1.3 数据流向

```
JSON文件 ──导入──> guali表 ──预计算──> guali_*扩展表 ──查询──> 前端展示
                    │                        │
                    ├──> 标签关联             │
                    │   (guali_tag表)         │
                    │                        │
                    └──> 预计算服务            │
                         (precalculate_       │
                          service.py)         │
                         ├── guali_time       │
                         ├── guali_yao        │
                         ├── guali_shensha    │
                         └── guali_gua        │
                                              │
                    查询时直接查预存表 ←────────┘
                    （不调用核心算法层）
```

**关键原则**：核心算法层只在导入卦例时调用一次，C1模块查询时**不调用任何核心算法**，所有数据直接从预存表读取。

## 二、JSON数据导入

> 本节内容已在 `.AIplan/json数据转换实现文档.md` 中有详细讨论，这里汇总关键点。

### 2.1 JSON字段映射

| JSON字段 | 数据库字段 | 转换规则 |
|---------|----------|---------|
| `dIniTime` | ask_time | 占问时间 |
| `dTitle` | ask_reason | 占问事由 |
| `dNote` | judgment | 占断内容（`\n`转换为换行） |
| `dyaolist` | ben_code + yao_bian_code | 符号转二进制代码 |

### 2.2 占问时间处理规则 ✅ 已确认

**规则**：
1. 从 `dTitle` 中提取 `MM.DD` 格式的日期（如果存在）
2. 从 `dIniTime` 中提取年份
3. 占问时间 = 年份 + MM.DD（**无论哪种情况，都不含时分**）

**示例**：
```
dTitle = "橡胶主连02.25夜盘开盘走势"
dIniTime = "2026-02-27 14:49:00"
→ 占问时间 = "2026-02-25"（用dTitle中的日期）

dTitle = "今天大盘走势"
dIniTime = "2026-02-27 14:49:00"
→ 占问时间 = "2026-02-27"（用dIniTime中的日期，仍不含时分）
```

### 2.3 dyaolist 转换规则 ✅ 已确认

**四种爻符号**：

| 符号 | 含义 | 本卦代码 | 爻变代码 |
|-----|------|---------|---------|
| `′` | 静阳爻 | 1 | 0 |
| `″` | 静阴爻 | 0 | 0 |
| `○` | 动阳爻 | 1 | 1 |
| `×` | 动阴爻 | 0 | 1 |

**示例**：
```
dyaolist = "○,′,″,○,′,′,"
↓
本卦代码 = 110111
爻变代码 = 100100
之卦代码 = 010011 (XOR计算)
```

### 2.4 完整导入流程

```
导入流程：
1. 解析JSON文件
2. 字段映射（dIniTime → zhanwen_time, dTitle → zhanwen_shiyou 等）
3. 代码转换（dyaolist → ben_code, yao_bian_code, zhi_code）
4. 存入 guali 主表
5. 调用预计算服务 ← 核心步骤
   ├── 计算 guali_time（时间干支、旬空）
   ├── 计算 guali_yao（六神、爻属性、伏神、暗动）
   ├── 计算 guali_shensha（神煞地支、是/带爻位）
   └── 计算 guali_gua（卦宫、宫位、特殊类型、反吟伏吟）
6. 更新 last_import_dinitime
```

### 2.5 增量导入机制 ✅ 已确认

**实现要点**：
1. 在 `system_config` 表中存储 `last_import_dinitime`
2. 每次导入时：
   - 读取配置中的 `last_import_dinitime`
   - 在JSON文件中搜索该时间戳
   - 只解析该时间戳**之前**的卦例（文件中靠前的卦例时间更晚）
3. 导入完成后更新配置

### 2.6 重复判断规则 ✅ 已确认

**规则**：只根据 `dIniTime` 判断重复
- 因为精确到分钟，一分钟内不会有多个卦例

## 六、卦象显示区域详细设计

### 6.1 整体结构（11列 × 6行） ✅ 已确认

参考用户提供的例图，采用左右对比布局：

| 列号 | 内容 | 说明 |
|-----|------|------|
| 1 | 六神 | 如"朱雀"、"青龙"等 |
| 2 | 易冒伏神 | 开关控制显示，默认关闭。6爻都有值，显示六亲+地支+五行 |
| 3 | 增删伏神 | 自动显示/隐藏。只在 zengshan_exists=TRUE 的爻位显示，显示六亲+地支+五行。飞神不显示（飞神就是本卦的爻） |
| 4 | 本卦爻信息 | 六亲+地支+五行（如"兄弟戌土"），天干开关控制 |
| 5 | 本卦爻绘制 | 阳爻`───`，阴爻`─ ─` |
| 6 | 动爻/暗动标记 | ○（动阳爻）、×（动阴爻）、△（暗动） |
| 7 | 本卦世应 | 标注"世"或"应" |
| 8 | 之卦爻信息 | 六亲+天干+地支+五行（仅变爻或全部，可切换）。天干开关与本卦同步控制 |
| 9 | 之卦爻绘制 | 阳爻`───`，阴爻`─ ─`（仅变爻或全部，可切换） |
| 10 | 之卦世应 | 标注"世"或"应" |

**数据来源说明**：

| 列 | 数据来源表 | 来源字段 |

| 1 六神 | guali_yao | liushen |
| 2 易冒伏神 | guali_yao | yimao_liuqin + yimao_dizhi |
| 3 增删伏神 | guali_yao | zengshan_exists, zengshan_liuqin + zengshan_dizhi |
| 4 本卦爻信息 | guali_yao | ben_liuqin + ben_tiangan + ben_dizhi |
| 5 本卦爻绘制 | guali_yao | ben_yao_type |
| 6 动爻/暗动标记 | guali_yao | is_dong, is_an_dong |
| 7 本卦世应 | guali_yao | ben_shi_ying |

| 9 之卦爻绘制 | guali_yao | zhi_yao_type |
| 10 之卦世应 | guali_yao | zhi_shi_ying（之卦整体的世应，6爻共享） |

### 6.2 爻位排列顺序 ✅ 已确认

```
第2行（二爻）：  螣蛇          子孙丑土  ─ ─        子孙丑土  ─ ─
第1行（初爻）：  勾陈          父母卯木  ─ ─        父母卯木  ─ ─
```

**列说明**（从左到右）：
- 第1列：六神
- 第2列：易冒伏神（开关控制）
- 第3列：增删伏神（自动显示）
- 第4列：本卦爻信息（六亲+地支+五行）
- 第5列：本卦爻绘制
- 第6列：动爻/暗动标记（○动阳爻、×动阴爻、△暗动）
- 第7列：本卦世应
- 第8列：之卦爻信息
- 第9列：之卦爻绘制
- 第10列：之卦世应

| 符号 | 含义 | 数据来源 |

| ○ | 动阳爻（阳变阴） | is_dong=TRUE, ben_yao_type=阳 |
| × | 动阴爻（阴变阳） | is_dong=TRUE, ben_yao_type=阴 |
| △ | 暗动（日支冲静爻） | is_an_dong=TRUE |

**说明**：暗动与动爻互斥，不会同时存在（暗动定义为静爻被日支冲）。

## 九、手动导入功能

### 9.1 入口

页面右上角"手动导入"按钮，点击后弹出弹窗。

### 9.2 弹窗内容

| 字段 | 是否必填 | 说明 |
|-----|---------|------|
| 占问时间 | ✅ 必填 | 如"2026-02-25" |
| 占问事由 | ✅ 必填 | 文本内容 |
| 占断内容 | ❌ 可选 | 文本内容，支持换行 |
| 本卦卦名 | ✅ 必填 | 下拉选择64卦之一 |
| 之卦卦名 | ❌ 可选 | 下拉选择64卦之一，留空则无动爻 |

### 9.3 卦名转代码逻辑 ✅ 已确认

用户输入卦名后，系统处理流程：
1. 用户选择本卦名（如"天火同人"）→ 系统查表获取 ben_code
2. 用户选择之卦名（如"风火家人"）→ 系统查表获取之卦代码 → XOR计算得到 yao_bian_code
3. 用户不选之卦名 → yao_bian_code = 000000

### 9.4 提交后预计算

手动导入提交后，后端自动触发预计算服务，与JSON导入流程一致：
- 计算 guali_time（时间干支、旬空）
- 计算 guali_yao（六神、爻属性、伏神、暗动）
- 计算 guali_shensha（神煞地支、是/带爻位）
- 计算 guali_gua（卦宫、宫位、特殊类型、反吟伏吟）

## 十、技术实现要点

### 10.1 前端路由设计

```
/guali           → 卦例主页面（左右分栏）
                   - 顶部有[手动导入]按钮（弹窗形式，非单独页面）
                   - 顶部有[JSON导入]按钮（跳转到JSON导入页）
/import          → JSON导入页（批量导入）
/tags            → 标签管理页
```

**说明**：
- **手动导入**采用弹窗形式，在 `/guali` 页面点击按钮后弹出，不单独设路由
- **JSON导入**是批量操作，需要单独页面展示进度和结果

### 10.2 后端API设计

```
GET    /api/guali              → 获取卦例列表（支持搜索、标签筛选）
GET    /api/guali/:id          → 获取卦例详情（联查guali_*扩展表）
PUT    /api/guali/:id          → 更新卦例
DELETE /api/guali/:id          → 删除单个卦例
DELETE /api/guali/batch        → 批量删除卦例
POST   /api/import/json        → 导入JSON文件
POST   /api/import/manual      → 手动导入单个卦例
GET    /api/tags               → 获取标签列表
POST   /api/tags               → 创建标签
PUT    /api/tags/:id           → 更新标签
DELETE /api/tags/:id           → 删除标签
POST   /api/guali/:id/tags     → 关联标签
```

### 10.3 数据查询

卦例详情展示时，**不调用核心算法层**，直接从预存表查询：

```python
def get_guali_detail(guali_id: int) -> dict:
    # 1. 从主表获取基础数据
    guali = db.get_guali(guali_id)

    # 2. 从 guali_* 扩展表获取预计算数据（导入时已算好）
    time_info = db.get_guali_time(guali_id)       # 时间干支、旬空
    yao_info = db.get_guali_yao(guali_id)          # 六神、爻属性、伏神、动爻暗动、世应
    shensha = db.get_guali_shensha(guali_id)       # 神煞地支值
    gua_ext = db.get_guali_gua(guali_id)            # 卦宫、宫位、特殊类型、反吟伏吟

    # 3. 组装返回数据（纯查表，无实时计算）
    return {
        'guali': guali,
        'time_info': time_info,
        'yao_info': yao_info,           # 6行，每行包含全部爻数据
        'shensha': shensha,
        'gua_ext': gua_ext,
    }
```

**关键点**：C1查询只涉及5张表——`guali`、`guali_time`、`guali_yao`、`guali_shensha`、`guali_gua`。不需要查询 `static_*` 表（static_* 表仅在导入时使用）。

### 10.4 性能考虑

- 卦例列表只显示基础信息，不查询扩展表
- 卦例详情直接查预存表，不调用核心算法层（纯SQL查询，无Python计算）
- 全部数据（纳甲、六亲、伏神、六神、神煞、世应）均从预存表读取

【用户发言】：10.1前端路由中是不是少了一个手动导入页?我看有json导入页但是没有手动导入页

【AI回复】：
手动导入采用**弹窗形式**，而不是单独页面。原因如下：
1. 手动导入是简单、低频操作，只需要填几个字段
2. 用户导入后希望立即看到新卦例出现在左侧列表
3. 弹窗形式更快捷，不需要页面跳转

JSON导入需要单独页面是因为：
- 涉及文件上传、解析进度展示
- 可能显示导入结果统计、错误报告

所以前端路由设计是合理的：
- `/guali` → 主页面（含手动导入弹窗）
- `/import` → JSON批量导入页面

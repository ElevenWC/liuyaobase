**用途**：存储每一条卦例的基本信息

| 字段名 | 类型 | 说明                    | 是否可修改 |
|-------|------|-----------------------|-----------|
| `id` | INT (主键, 自增) | 卦例唯一编号                | ❌ |

- `id` 是数据库自增主键，删除卦例后不会变化

|-------|------|------|

### 1.11 增删伏神表（static_fushen_zengshan）—— 64卦固定属性表 ✅

**用途**：预存64卦每一爻位的增删伏神信息（伏神伏在哪个爻位，飞神是什么）

| 字段名 | 类型 | 说明 |
|-------|------|------|
| `code` | VARCHAR(6) (主键1) | 卦代码 |
| `yao_index` | INT (主键2) | 爻位（1-6），伏神伏在此爻位下 |
| `missing_liuqin` | VARCHAR(10) NOT NULL | 缺失的六亲（如"妻财"） |
| `fushen_dizhi` | VARCHAR(1) NOT NULL | 伏神地支 |
| `fushen_liuqin` | VARCHAR(10) NOT NULL | 伏神六亲（根据本卦卦宫五行与伏爻地支五行计算） |
| `feishen_dizhi` | VARCHAR(1) NOT NULL | 飞神地支（与伏神在同一爻位） |
| `feishen_liuqin` | VARCHAR(10) NOT NULL | 飞神六亲（与伏神在同一爻位） |

**设计说明**：
- **伏神**：隐藏在本卦某爻位下面的神煞
- **飞神**：本卦某爻位上原有的爻（伏神就藏在飞神下面）
- 增删伏神规则：只显示卦中**缺失六亲**对应的伏神
- 每个卦可能缺失0-2个六亲（大多数缺1个）
- 64卦约有**64条记录**（部分卦可能有2条）

**示例数据**：
```
code='101111' (天火同人，离宫，卦宫五行=火)

yao_index=3 (三爻)
missing_liuqin='妻财' (卦中缺失妻财)
fushen_dizhi='酉' (根据增删伏神规则得出)
fushen_liuqin='妻财' (离宫火生酉金→妻财)
feishen_dizhi='亥' (三爻本来的地支是亥)
feishen_liuqin='官鬼' (离宫火克亥水→官鬼)
```

## 1.13 预计算模块设计说明 ✅

### 两套预计算表的区别

本项目采用**两套预计算表**，分别处理不同类型的数据：

| 预计算类型 | 命名规则 | 数据量 | 用途 | 示例表 |
|-----------|---------|--------|------|--------|
| **64卦固定属性** | `static_*` | 384条 | 卦例显示、基础计算 | static_gua_yao_info |
| **卦例动态属性** | `guali_*` | N×9行/卦例 | 复杂检索 | guali_time, guali_yao |

**关键区别**：
- `static_*`表：存储64卦的固定属性（纳甲地支、伏神等），所有卦例共享
- `guali_*`表：存储每个卦例的动态属性（六神、神煞、暗动等），由占问时间决定

### 为什么需要预计算表？

**核心思路**：将六爻系统中**固定不变**或**可预先计算**的数据存入数据库，提升检索效率。

### static_* 表（64卦固定属性）

| 数据类型 | 是否固定 | 存储方式 | 说明 |
|---------|---------|---------|------|
| 纳甲地支 | ✅ 固定 | 预存数据库 | 每个卦的6个地支永远不变 |
| 爻天干 | ⚠️ 半固定 | 预存两套 | 28个乾坤相关卦需要根据节气选择 |
| 本卦六亲 | ✅ 固定 | 预存数据库 | 卦宫固定→卦宫五行固定→六亲固定 |
| 增删伏神 | ✅ 固定 | 预存数据库 | 每个卦缺什么六亲、伏神是什么都是固定的 |
| 易冒伏神 | ✅ 固定 | 预存数据库 | 规则固定，每个爻位的伏神固定 |

### guali_* 表（卦例动态属性）

| 数据类型 | 存储方式 | 说明 |
|---------|---------|------|
| 时间干支 | guali_time | 年柱、月柱、日柱、旬空 |
| 神煞状态 | guali_shensha | 神煞地支 + "是/带"爻位列表 |
| 卦类属性 | guali_gua | 卦宫、宫位、特殊类型、反吟伏吟 |
| 爻类属性 | guali_yao | 六神、暗动、五种来源（本卦/变爻/之卦/伏神） |

**注意**：guali_*表在**导入卦例时计算并存储**，支持复杂检索模块的索引查询。

### 预计算模块的收益

| 方面 | 收益 |
|-----|------|
| **查询性能** | 直接查表，无需每次计算纳甲、六亲等 |
| **数据一致性** | 64卦的固定数据只需维护一份 |
| **代码简洁** | 减少重复计算逻辑 |
| **存储成本** | 384×3=1152条记录，可忽略不计 |

### 查询示例

**场景**：查询卦例ID=1的卦爻详情

```sql
-- 1. 获取卦例基础信息
SELECT ben_code, yao_bian_code FROM guali WHERE id = 1;
-- 假设返回：ben_code='101111'

-- 2. 获取卦名、卦宫、五行
SELECT name, palace, element FROM bagong_gua WHERE code = '101111';
-- 返回：天火同人, 离宫, 火

-- 3. 获取6个爻的预计算属性（一次查询获取所有）
SELECT yao_index, dizhi, liuqin, tiangan
FROM gua_yao_info
WHERE code = '101111'
ORDER BY yao_index DESC;
-- 返回6行：
-- 上爻: 戌, 兄弟, (空)
-- 五爻: 申, 子孙, (空)
-- ...

-- 4. 获取增删伏神
SELECT missing_liuqin, fushen_dizhi, fushen_liuqin
FROM fushen_zengshan
WHERE code = '101111';
-- 返回：缺失妻财 → 伏神酉金妻财

-- 5. 获取易冒伏神（如果用户开启）
SELECT yao_index, fushen_dizhi, fushen_liuqin
FROM fushen_yimao
WHERE code = '101111'
ORDER BY yao_index DESC;
-- 返回6行
```

### 季节判断逻辑（用于选择天干）

```python
def get_tiangan(code: str, yao_index: int, solar_term: str) -> str:
    """
    根据节气获取正确的天干

    @param code: 卦代码
    @param yao_index: 爻位(1-6)
    @param solar_term: 当前节气（用于判断夏至前/后）
    @return: 天干字符
    """
    info = query_gua_yao_info(code, yao_index)

    # 普通卦：直接返回tiangan
    if info.tiangan:
        return info.tiangan

    # 乾坤相关卦：根据节气选择
    # 夏至→冬至：用tiangan_summer
    # 冬至→夏至：用tiangan_winter
    if is_after_xiazhi(solar_term):
        return info.tiangan_summer
    else:
        return info.tiangan_winter
```

### 【问】Q10：关于数据库编程的好奇

**用户提问**：
> 对于数据库,我比较好奇怎么编写?是有专门应对它的编程语言吗?Mysql和什么东西比较像呢?和Excel本体?还是Python?比如我们要构建一个数据库是像用Python语言写一个程序一样吗?还是像用Excel创建一个表呢?

**我的回答**：

这是一个很好的问题！让我用简单的方式解释：

### 数据库编程是什么？

**类比**：
| 对比项 | Excel | 数据库 |
|-------|-------|--------|
| 创建表的方式 | 图形界面点击 | 写SQL语句或用代码 |
| 数据操作 | 手动输入、复制粘贴 | 写SQL语句或用代码 |
| 编程语言 | VBA宏 | SQL + Python/Java等 |

### 数据库是怎么"编写"的？

有两种方式：

**方式1：直接写SQL语句**
```sql
-- 创建表
CREATE TABLE guali (
    id INT AUTO_INCREMENT PRIMARY KEY,
    zhanwen_shiyou TEXT
);

-- 插入数据
INSERT INTO guali (zhanwen_shiyou) VALUES ('橡胶走势');
```

**方式2：用Python代码（我们采用的方式）**
```python
from sqlmodel import SQLModel, Field

class Guali(SQLModel, table=True):
    id: int = Field(default=None, primary_key=True)
    zhanwen_shiyou: str

# 创建表
SQLModel.metadata.create_all(engine)
```

### 数据库像什么？

- **像Excel**：都是存数据的，有表、有行、有列
- **像Python**：可以用代码来操作
- **不像任何东西**：有自己的语言（SQL），是独立的系统

### 我们的系统是怎么构建的？

```
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│  Python代码      │     │  SQLModel ORM   │     │  MySQL数据库    │
│  (定义表结构)    │ ──→ │  (自动转换)      │ ──→ │  (真正存储数据) │
└─────────────────┘     └─────────────────┘     └─────────────────┘
```

1. 我们用Python定义表结构（写一个类）
2. SQLModel自动转换成SQL语句
3. MySQL执行SQL语句，创建表

**总结**：你不需要学太多SQL，我们主要用Python代码来操作数据库！

## 一、技术栈选型

### 1.1 已确认的技术栈 ✅

| 层级 | 技术 | 说明 |
|-----|------|------|
| **后端框架** | FastAPI | Python 现代Web框架，自动生成API文档 |
| **ORM** | SQLModel | SQLAlchemy + Pydantic 融合，类型安全 |

### 1.2 技术选型理由

| 技术 | 选型理由 |
|-----|---------|
| **FastAPI** | 1. 现代、快速（基于Starlette和Pydantic）<br>2. 自动生成 Swagger API 文档<br>3. 类型提示支持好<br>4. 异步支持 |
| **SQLModel** | 1. SQLAlchemy 的强大 + Pydantic 的类型安全<br>2. 一个类既是模型也是 Schema<br>3. 减少代码重复 |

### 6.2 预计算 vs 实时计算的分工

| 数据类型        | 来源 | 原因                   |
|-------------|------|----------------------|
| 纳甲地支        | 预计算表 `gua_yao_info` | 64卦×6爻固定不变           |
| 天干          | 预计算表 `gua_yao_info` | 64卦×6爻固定不变           |
| 六亲（本卦时）     | 预计算表 `gua_yao_info` | 64卦×6爻固定不变           |
| 增删伏神        | 预计算表 `fushen_zengshan` | 每卦固定                 |
| **六亲（之卦时）** | **实时计算** | 之卦的地支来自本卦纳甲，但六亲需重新计算 |
| **六神**      | **实时计算** | 依赖日干（动态）             |
| **神煞**      | **实时计算** | 依赖日干日支（动态）           |
| **旬空**      | **实时计算** | 依赖日柱（动态）             |

**变爻六亲的计算说明**：

之卦的爻的六亲需要实时计算，因为：
1. 之卦爻的地支 = 其作为本卦时该爻位的纳甲地支（已知，从预计算表获取）
2. 之卦爻的六亲 = 本卦卦宫五行 与 之卦爻地支五行 的关系（需计算）
3. 之卦的爻根据本卦卦宫和自身地支计算出六亲后,提取其中对应爻位作为变爻

```python
def calculate_bian_yao_liuqin(palace_element: str, bian_yao_dizhi: str) -> str:
    """
    计算变爻的六亲
    @param palace_element: 本卦卦宫五行（如"火"）
    @param bian_yao_dizhi: 变爻地支（如"未"）
    @return: 六亲（如"子孙"）
    """
    dizhi_element = get_dizhi_element(bian_yao_dizhi)  # 未→土
    return calculate_liuqin(palace_element, dizhi_element)  # 火生土→子孙
```

## 附录A：后端基础知识

### A.1 什么是后端？

后端是运行在服务器上的程序，负责：
1. **接收前端请求**：前端通过 HTTP 请求与后端通信
2. **处理业务逻辑**：计算、验证、决策
3. **操作数据库**：增删改查
4. **返回响应**：把处理结果返回给前端

### A.2 什么是 API？

API（Application Programming Interface）是前后端通信的"协议"。

**REST API** 是一种设计风格：
- 使用 HTTP 方法表示操作：GET（查）、POST（增）、PUT（改）、DELETE（删）
- 使用 URL 表示资源：`/api/guali/54` 表示 ID=54 的卦例

```
前端                              后端
  │                                │
  │  GET /api/guali/54             │
  │ ─────────────────────────────→ │
  │                                │ 查询数据库
  │                                │ 调用算法
  │  { "id": 54, "name": "..." }   │
  │ ←───────────────────────────── │
  │                                │
```

### A.3 什么是 ORM？

ORM（Object-Relational Mapping）是"对象-关系映射"。

**问题**：数据库用的是 SQL 语言，Python 用的是对象，两者不兼容。

**解决**：ORM 把 Python 对象自动转换成 SQL 语句。

```python
# 不用 ORM，手写 SQL（麻烦）
cursor.execute("SELECT * FROM guali WHERE id = 54")

# 用 ORM，操作对象（简洁）
guali = session.get(Guali, 54)
```

### A.4 什么是分层架构？

分层是把代码按职责分开：

| 层 | 职责 | 举例 |
|---|------|------|
| **API层** | 接收请求、返回响应 | `@router.get("/guali/{id}")` |
| **Service层** | 业务逻辑 | 判断权限、组合数据 |
| **CRUD层** | 数据库操作 | 增删改查 |
| **Core层** | 纯算法 | 六亲计算、六神计算 |

**好处**：
- 职责清晰，便于维护
- 算法层可独立测试
- 换数据库只需改CRUD层

```python
from sqlmodel import SQLModel, Field
from typing import Optional

class Guali(SQLModel, table=True):
    """卦例表"""
    id: Optional[int] = Field(default=None, primary_key=True)
    zhanwen_time: str
    zhanwen_shiyou: str
    zhanduan: Optional[str] = None
    ben_code: str
    yao_bian_code: str
```

### C.2 数据库操作

```python
from sqlmodel import Session, select

# 创建
with Session(engine) as session:
    guali = Guali(
        zhanwen_time="2026-02-25",
        zhanwen_shiyou="测试",
        ben_code="101111",
        yao_bian_code="000000"
    )
    session.add(guali)
    session.commit()
    session.refresh(guali)  # 获取自增ID
    print(guali.id)

# 查询
with Session(engine) as session:
    statement = select(Guali).where(Guali.id == 1)
    guali = session.exec(statement).first()

# 查询列表
with Session(engine) as session:
    statement = select(Guali).order_by(Guali.zhanwen_time.desc())
    guali_list = session.exec(statement).all()
```

### C.3 SQLModel vs SQLAlchemy

| 对比 | SQLAlchemy | SQLModel |
|-----|------------|----------|
| 定义模型 | 需要单独定义 | 一个类即可 |
| 类型提示 | 不支持 | 原生支持 |
| Pydantic集成 | 需要额外配置 | 原生支持 |
| 学习曲线 | 较陡 | 较平 |

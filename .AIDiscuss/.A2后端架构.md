## 一、技术栈选型

### 1.1 已确认的技术栈

| 层级 | 技术 | 说明 |
|-----|------|------|
| **后端框架** | FastAPI | Python 现代Web框架，自动生成API文档 |
| **ORM** | SQLModel | SQLAlchemy + Pydantic 融合，类型安全 |
| **数据库** | MySQL | 关系型数据库 |
| **前端框架** | Vue.js 3 | 前端框架 |
| **前后端通信** | REST API | 标准 HTTP API |
| **股票数据** | AKShare | Python 金融数据接口（C4专用），限流 0.5 QPS |
| **农历计算** | lunar-python | 干支转换、节气日期（B1/C4使用） |

### 1.2 技术选型理由

| 技术 | 选型理由 |
|-----|---------|
| **FastAPI** | 现代、快速（基于Starlette和Pydantic）；自动生成 Swagger API 文档；类型提示支持好；异步支持 |
| **SQLModel** | SQLAlchemy 的强大 + Pydantic 的类型安全；一个类既是模型也是 Schema；减少代码重复 |
| **MySQL** | 成熟稳定；社区资源丰富 |
| **AKShare** | 免费开源，覆盖A股/期货历史数据，无需API Key |

## 二、已确认的架构决策

### 2.1 分层架构

```
┌─────────────────────────────────────────────────────────────────┐
│                        前端 (Vue.js)                            │
│    页面组件 → 状态管理(Pinia) → API调用层 → HTTP请求              │
└─────────────────────────────────────────────────────────────────┘
                              │
                              │ HTTP REST API
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│                        后端 (FastAPI)                           │
├─────────────────────────────────────────────────────────────────┤
│  API层 (Routers)     → 接收请求、参数验证、返回响应              │
│  Service层 (Services) → 业务逻辑处理                            │
│  数据访问层 (CRUD)    → 数据库操作封装                           │
│  核心算法层 (Core)    → 六爻卦理计算（纯函数，不依赖数据库）      │
└─────────────────────────────────────────────────────────────────┘
                              │
                              │ SQLModel ORM
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│                        数据库 (MySQL)                           │
│    guali / tag / guali_* / static_* / stock_* / bagong_gua ...  │
└─────────────────────────────────────────────────────────────────┘
```

### 2.2 核心算法层的设计

核心算法层的特点：
- **纯Python实现**，不依赖数据库
- **可独立测试**，便于验证算法正确性
- **只在导入卦例时调用一次**，计算结果存入预存表（guali_* / static_*）
- **查询时不调用**（C1/C3/C4直接查预存表，C2实时计算互卦/八宫变化）

### 2.3 预存表架构（最重要的架构决策）

```
导入卦例时（一次性计算）：
  import_service.py → precalculate_service.py → 核心算法层(core/)
  → 计算结果存入 guali_* / static_* 预存表

查询卦例时（直接查表）：
  C1卦例显示 → 查5张表（guali + guali_*）
  C3复杂检索 → 查预存表 + MySQL存储函数
  C4股票关联 → 查5张表 + stock_*表
  （三个模块都不调用核心算法层）
```

## 五、API设计汇总

### 5.1 卦例模块 API（C1）

```
GET    /api/guali                      → 获取卦例列表（支持搜索、标签筛选、分页）
GET    /api/guali/{id}                 → 获取卦例详情（查5张预存表拼装）
PUT    /api/guali/{id}                 → 更新卦例（占问事由、占断内容）
DELETE /api/guali/{id}                 → 删除单个卦例
DELETE /api/guali/batch                → 批量删除卦例
POST   /api/guali/{id}/tags            → 为卦例关联标签
DELETE /api/guali/{id}/tags/{tag_id}   → 解除卦例的标签关联
```

### 5.2 导入模块 API

```
POST   /api/import/json                → 导入JSON文件（批量，触发预计算）
POST   /api/import/manual              → 手动导入单个卦例（触发预计算）
GET    /api/import/status              → 获取导入状态
```

### 5.3 标签模块 API

```
GET    /api/tags                       → 获取标签列表（树形结构）
POST   /api/tags                       → 创建标签
PUT    /api/tags/{id}                  → 更新标签
DELETE /api/tags/{id}                  → 删除标签
GET    /api/tags/{id}/guali            → 获取该标签下的所有卦例
```

### 5.4 解卦模块 API（C2）

```
GET    /api/jiegua/bagong/{gua_code}   → 获取指定卦的八宫变化
GET    /api/jiegua/hugua/{gua_code}    → 获取指定卦的互卦
GET    /api/jiegua/graph/{graph_type}  → 获取网络图谱数据
GET    /api/jiegua/guaci/{gua_code}    → 获取卦爻辞
```

### 5.5 检索模块 API（C3）

```
POST   /api/search                     → 执行复杂检索（核心接口）
GET    /api/search/schemes             → 获取推荐方案列表
POST   /api/search/export              → 导出检索结果
```

**检索请求体结构**（SearchRequest Schema）：
```json
{
  "conditions": [
    {
      "id": "cond_1",
      "field": "ben_liuqin",
      "operator": "equals",
      "value": "妻财",
      "scope": "ben_gua"
    }
  ],
  "logic": "cond_1",
  "pagination": { "page": 1, "page_size": 50 }
}
```

### 5.6 股票模块 API（C4）

```
GET    /api/stock/search?keyword=      → 搜索股票（调用AKShare）
GET    /api/stock/list                 → 获取已添加的股票列表
POST   /api/stock                      → 添加新股票 + 触发首次数据获取
DELETE /api/stock/{id}                 → 删除股票
POST   /api/stock/{id}/update          → 手动更新数据（从AKShare获取最新）
GET    /api/stock/{id}/klines?period=  → 获取K线数据（day/month/year）
GET    /api/stock/{id}/minute?date=    → 获取指定日期的分时数据
GET    /api/stock/{id}/guacases?date=  → 获取指定日期关联的卦例列表
PUT    /api/stock/{id}/guacase/{guali_id}/zhanyan → 修改卦例占验情况
```

### 5.7 API 响应格式

**成功响应**：
```json
{
  "code": 200,
  "data": { ... },
  "message": "success"
}
```

**错误响应**：
```json
{
  "code": 400,
  "data": null,
  "message": "错误原因描述"
}
```

## 附录A：后端基础知识

### A.1 什么是后端？

后端是运行在服务器上的程序，负责：
1. **接收前端请求**：前端通过 HTTP 请求与后端通信
2. **处理业务逻辑**：计算、验证、决策
3. **操作数据库**：增删改查
4. **返回响应**：把处理结果返回给前端

### A.2 什么是 API？

API（Application Programming Interface）是前后端通信的"协议"。

**REST API** 是一种设计风格：
- 使用 HTTP 方法表示操作：GET（查）、POST（增）、PUT（改）、DELETE（删）
- 使用 URL 表示资源：`/api/guali/54` 表示 ID=54 的卦例

```
前端                              后端
  │                                │
  │  GET /api/guali/54             │
  │ ─────────────────────────────→ │
  │                                │ 查询数据库
  │                                │ 调用算法
  │  { "id": 54, "name": "..." }   │
  │ ←───────────────────────────── │
  │                                │
```

### A.3 什么是 ORM？

ORM（Object-Relational Mapping）是"对象-关系映射"。

**问题**：数据库用的是 SQL 语言，Python 用的是对象，两者不兼容。
**解决**：ORM 把 Python 对象自动转换成 SQL 语句。

```python
# 不用 ORM，手写 SQL（麻烦）
cursor.execute("SELECT * FROM guali WHERE id = 54")

# 用 ORM，操作对象（简洁）
guali = session.get(Guali, 54)
```

### A.4 什么是分层架构？

分层是把代码按职责分开：

| 层 | 职责 | 举例 |
|---|------|------|
| **API层** | 接收请求、返回响应 | `@router.get("/guali/{id}")` |
| **Service层** | 业务逻辑 | 判断权限、组合数据 |
| **CRUD层** | 数据库操作 | 增删改查 |
| **Core层** | 纯算法 | 六亲计算、六神计算 |

### 3.4 扩展性分析

**增加一个新神煞（如"文昌"）**：
- 只需增加 **8个字段**（2状态 × 4来源）
- 不影响爻表结构

**vs 存在爻表**：
- 需要增加 **48个字段**（6爻 × 2状态 × 4来源）
- 爻表变得臃肿

**结论**：存在神煞表的方案扩展性更好！

### 3.5 检索示例详解

#### 示例1：查询"动爻带干禄"的卦例

```sql
SELECT DISTINCT g.*
FROM guali g
JOIN guali_shensha s ON g.id = s.guali_id
JOIN guali_yao y ON g.id = y.guali_id
WHERE y.is_dong = TRUE
  AND FIND_IN_SET(y.yao_position, s.ben_dai_ganlu) > 0;
```

**逐行解释**：

| 代码 | 含义 |
|------|------|
| `FROM guali g` | 从主表 guali 开始，别名为 g |
| `JOIN guali_shensha s ON g.id = s.guali_id` | 关联神煞表，获取神煞信息（包括"带干禄的爻位列表"） |
| `JOIN guali_yao y ON g.id = y.guali_id` | 关联爻表，获取每爻的属性（包括"是否动爻"） |
| `WHERE y.is_dong = TRUE` | 筛选条件1：只看动爻 |
| `FIND_IN_SET(y.yao_position, s.ben_dai_ganlu)` | 筛选条件2：检查这个爻位是否在"本卦带干禄"列表中 |
| `> 0` | FIND_IN_SET 返回位置（1,2,3...）或 0（未找到），>0 表示找到了 |
| `SELECT DISTINCT g.*` | 返回不重复的卦例记录 |

**FIND_IN_SET 函数详解**：

```sql
FIND_IN_SET(needle, haystack)
-- needle: 要查找的值
-- haystack: 逗号分隔的字符串

-- 示例：
FIND_IN_SET('3', '1,3,5')  → 返回 2（3在列表中排第2位）
FIND_IN_SET('4', '1,3,5')  → 返回 0（4不在列表中）
FIND_IN_SET('1', '')       → 返回 0（空列表）
```

**执行流程图**：

```
┌─────────────────────────────────────────────────────────────────┐
│ 假设卦例数据：                                                    │
│ guali_yao 表：                                                   │
│   爻位1: is_dong=FALSE                                           │
│   爻位2: is_dong=FALSE                                           │
│   爻位3: is_dong=TRUE   ← 动爻                                   │
│   爻位4: is_dong=TRUE   ← 动爻                                   │
│   爻位5: is_dong=FALSE                                           │
│   爻位6: is_dong=FALSE                                           │
│                                                                  │
│ guali_shensha 表：                                               │
│   ben_dai_ganlu = "1,4,6"  ← 带干禄的爻位是1、4、6                │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│ WHERE 条件判断：                                                  │
│                                                                  │
│ 爻位1: is_dong=FALSE → 跳过                                      │
│ 爻位2: is_dong=FALSE → 跳过                                      │
│ 爻位3: is_dong=TRUE, FIND_IN_SET(3, "1,4,6")=0 → 不满足          │
│ 爻位4: is_dong=TRUE, FIND_IN_SET(4, "1,4,6")=2 > 0 → ✅ 满足！   │
│ 爻位5: is_dong=FALSE → 跳过                                      │
│ 爻位6: is_dong=FALSE → 跳过                                      │
│                                                                  │
│ 结果：第4爻既是动爻又带干禄，返回此卦例                             │
└─────────────────────────────────────────────────────────────────┘
```

#### 示例2：查询"世爻是驿马"的卦例

```sql
SELECT DISTINCT g.*
FROM guali g
JOIN guali_shensha s ON g.id = s.guali_id
JOIN guali_yao y ON g.id = y.guali_id
WHERE y.ben_shi_ying = '世'
  AND FIND_IN_SET(y.yao_position, s.ben_is_yima) > 0;
```

**与示例1的区别**：

| 对比项 | 示例1（动爻带干禄） | 示例2（世爻是驿马） |
|--------|-------------------|-------------------|
| 筛选条件1 | `y.is_dong = TRUE` | `y.ben_shi_ying = '世'` |
| 筛选条件2 | `s.ben_dai_ganlu`（带） | `s.ben_is_yima`（是） |
| 逻辑 | 动爻 AND 带干禄 | 世爻 AND 是驿马 |

**注意**：神煞状态字段（如 `ben_dai_ganlu`）不需要索引，因为：
- 存储格式是逗号分隔的字符串（如 "1,3,5"）
- 使用 `FIND_IN_SET()` 函数查询
- MySQL 无法对这种查询使用索引

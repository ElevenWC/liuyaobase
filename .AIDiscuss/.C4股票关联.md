## 一、模块概述

### 1.1 模块定位

C4股票关联模块将股票/期货K线图与卦例系统关联起来，使用户可以在查看走势图的同时看到对应日期的卦例。

### 1.2 核心数据流

```
用户搜索股票名称 → AKShare获取历史数据 → 存入本地数据库
                                                  ↓
                                    绘制K线图（日K/月K/年）
                                                  ↓
用户点击K线 → 通过标签查找对应卦例 → 弹出卦例详情浮窗 + 分时图浮窗
```

### 1.3 数据来源

| 数据类型 | 来源 | 存储位置 | 更新方式 |
|---------|------|---------|---------|
| 股票历史数据 | AKShare API | stock_day_kline / stock_minute_kline | 用户手动触发更新 |
| 期货历史数据 | AKShare API | futures_session_kline（构想中） | 用户手动触发更新 |
| 卦例数据 | 系统已有 | guali 表 | 已通过C1导入 |

```
│  │                                                                    │  │
│  └────────────────────────────────────────────────────────────────────┘  │

```

**设计要点**（来自 `股票-卦例显示规则.md`）：
- K线图横轴除了公历时间外，还需要显示**月柱、日柱**标志（来自 `guali_time` 表）
- 日K图中双击某根K线 → 弹出分时图浮窗 + 卦例浮窗
- K线有三种显示形式（见 3.3 节）

### 3.2 K线周期切换

切换K线周期时，数据聚合方式不同：

| 周期 | 股票数据来源 | 期货数据来源 | 卦例匹配方式 |
|------|------------|------------|------------|
| 日K | stock_day_kline 表 | futures_session_kline 聚合为日 | 日期精确匹配 |
| 月K | stock_day_kline 聚合 | futures_session_kline 聚合 | **农历月**聚合（节气→节气） |
| 年K | stock_day_kline 聚合 | — | **农历年**聚合 |

**关键设计**（来自 `.C4股票关联.txt` 第2条）：
- 月K和年K都是农历月/年，而非公历年月
- 需要根据节气来聚合（如卯月 = 惊蛰→清明）
- 农历月K的聚合需要 `lunar-python` 库来判断节气日期

### 3.3 K线三种样式

| 类型 | 条件 | 阳线（涨） | 阴线（跌） |
|------|------|----------|----------|
| 普通K线 | 该日无卦例 | 空心红色 | 空心绿色 |
| 应验K线 | 有卦例 + 占验=应验 | **实心**红色 | **实心**绿色 |
| 待验K线 | 有卦例 + 占验=模糊/不验 | 空心红色+**灰色填充** | 空心绿色+**灰色填充** |

## 四、卦例浮窗

### 4.2 日卦、月卦、年卦的区分

**核心概念**：卦例按其占问的时间范围分为三种类型，对应不同的K线周期：

| 卦例类型 | 占问内容示例 | 对应K线周期 | 匹配方式 |
|---------|------------|:----------:|---------|
| 日卦 | "ST生物今日走势"、"橡胶02.25夜盘" | 日K | 占问日期 = K线日期 |
| 月卦 | "ST生物卯月走势"、"橡胶本月行情" | 月K | 占问农历月 = K线农历月 |
| 年卦 | "ST生物丙午年走势" | 年K | 占问农历年 = K线农历年 |

**区分方式**：通过**标签**来标记卦例的类型。

```
标签结构（方案B：卦例同时打两个标签）：
├── 标的标签：股票-ST生物
└── 类型标签：日卦 / 月卦 / 年卦（独立标签）
```

一个卦例打上两个标签即完成分类，C4根据类型标签筛选对应的卦。

### 4.3 日K点击 → 双浮窗

双击某根日K线后，弹出两个浮窗（与月K/年K不同，日K只显示**日卦**）：

```
┌────────────────┐     ┌──────────────────────────┐
│   分时图浮窗    │     │      卦例详情浮窗          │
│   (左侧)       │     │      (右侧)               │
│                │     │                            │
│  2026-02-25    │     │  本卦：天火同人             │
│  开盘：XX      │     │  之卦：风火家人             │
│  收盘：XX      │     │  （完整卦象显示，同C1）     │
│  最高：XX      │     │                            │
│  最低：XX      │     │  六神 六亲 地支 世应 卦象  │
│  成交量：XX    │     │  玄武 兄弟 戌土      ───   │
│                │     │  ...                       │
│  [分时曲线图]  │     │                            │
│                │     │  [卦爻辞] [修改占验]       │
│                │     │                            │
│  [×]           │     │  [×]                       │
└────────────────┘     └──────────────────────────┘
```

**设计要点**：
- 卦例浮窗按C1标准绘制与显示
- 浮窗可自由移动、多开
- 点击卦名显示卦爻辞浮窗
- 浮窗中有[修改占验]按钮
- 若当日有多个日卦，每个卦例弹出独立的浮窗
- 若当日无日卦，浮窗显示"该日无对应卦例"

### 4.4 月K点击 → 月卦浮窗

切换到月K后，点击某月K线：
- 弹出该**农历月**对应的**月卦**（占当月走势的卦例，通常只有一卦）
- 如果该月没有月卦，显示"该月无对应卦例"

### 4.5 年卦显示

在月K线的横轴坐标上显示**年份标签**：
- 点击年份标签 → 弹出该农历年对应的**年卦**
- 如果该年没有年卦，显示"该年无对应卦例"

## 五、标签关联机制

### 5.1 卦例与标的的关联方式

**方案**：通过标签系统关联（来自 `.C4股票关联.txt` 第11条）。

```
标签结构（方案B：卦例同时打两个标签）：
├── 标的标签（关联 stock_info.tag_id）
│   ├── 股票-ST生物
│   ├── 股票-指南针
│   └── 期货-橡胶
└── 类型标签（独立标签，与标的标签并列）
    ├── 日卦（默认）
    ├── 月卦
    └── 年卦
```

一个卦例同时打两个标签：标的标签（如"股票-ST生物"）+ 类型标签（如"月卦"）。C4查询时通过两个标签联合过滤。

**关联流程**：
1. 用户创建股票/期货标的时，自动创建对应二级标签（或在已有标签中选择）
2. 在C1卦例管理界面，用户可为卦例打上标签（如"ST生物"）
3. C4界面中，根据当前查看的标的找到关联标签，再通过 `guali_tag` 表找到所有关联卦例
4. 将这些卦例按日期组织成"卦例池"，与K线日期匹配

**数据查询路径**：
```
stock_info.tag_id → tag表 → guali_tag表 → guali表 → 卦例池
```

### 5.2 关联方式确认：仅使用标签匹配 ✅

**最终决定**：仅使用**标签匹配**方式，不自动通过占问事由搜索。

用户需要手动为卦例打上标的标签（如"ST生物"）+ 卦类型标签（如"日卦"/"月卦"/"年卦"）。

**需要的功能支撑**：

| 功能 | 所属模块 | 说明 |
|------|:------:|------|
| 创建标签（二级结构） | C1 | 已设计，如"股票-ST生物" |
| 单个卦例打标签 | C1 | 已设计，卦例详情页点击标签区域 |
| **批量打标签** | C1 | **需要新增**：在C1卦例列表中多选卦例后，批量添加标签 |
| 按标签筛选卦例 | C1 | 已设计，点击标签即可筛选 |

**批量打标签流程**（C1新增功能）：

```
1. 在C1卦例列表页，用户勾选多个卦例（复选框）
2. 点击"批量打标签"按钮
3. 弹出标签选择器（树形结构：一级→二级→三级分类）
4. 用户选择目标标签（如"股票-ST生物-日卦"）
5. 确认后，批量在 guali_tag 表中创建关联记录
```

## 六、期货特殊处理

### 6.1 期货与股票的关键差异

| 特性 | 股票 | 期货 |
|------|------|------|
| 交易时段 | 9:30-11:30, 13:00-15:00 | 含夜盘（21:00-次日凌晨） |
| 日K定义 | 自然日 | 前一天夜盘+当天日盘 |
| 主力合约 | 不存在 | 需要跟踪主力合约切换 |
| 数据粒度 | 日K + 分时 | 分时段 → 聚合为日K |
| 夜盘归属 | 不存在 | 夜盘归入下一交易日，但占卜不按此计算 |

### 6.2 期货夜盘分类

（来自 `.C4股票关联.txt` 第3-4条）

| 类型 | 夜盘时间 | 典型品种 | 日K聚合方式 |
|------|---------|---------|------------|
| 无夜盘 | — | 部分农产品 | 日盘数据直接作为日K |
| 短夜盘 | 21:00-23:00 | 橡胶、螺纹钢 | 夜盘+次日日盘 = 一根日K |
| 长夜盘 | 21:00-次日02:30 | 黄金、白银、原油 | 夜盘+次日日盘 = 一根日K |

**设计决策**：不区分长短夜盘，统一将日盘+夜盘聚合为一根日K。使用自定义聚合逻辑（不能用标准的"自然日"聚合方式）。



### 6.3 主力合约切换

期货存在主力合约切换问题。例如橡胶从 ru2505 切换到 ru2509 时，K线图需要连续显示。

**设计决策**：使用 AKShare 的"主力连续"合约数据（如 ru888），K线图数据天然连续，无需手动处理合约切换。

## 七、农历月K/年K聚合

### 7.1 聚合规则

（来自 `.C4股票关联.txt` 第2条）

月K和年K必须按**农历（节气）**而非公历聚合：

| 农历月 | 节气范围 | 示例（2026年） |
|--------|---------|---------------|
| 寅月 | 立春→惊蛰 | 2月4日→3月5日 |
| 卯月 | 惊蛰→清明 | 3月5日→4月5日 |
| 辰月 | 清明→立夏 | 4月5日→5月5日 |
| ... | ... | ... |

**月K聚合算法**：
```python
def aggregate_monthly_kline(day_klines: list, jieqi_dates: list) -> list:
    """
    将日K数据按节气范围聚合为农历月K
    - day_klines: 日K数据列表
    - jieqi_dates: 节气日期列表（从lunar-python获取）
    - 返回: 月K数据列表（开、高、低、收、成交量）
    """
    monthly_bars = []
    for month_start, month_end in zip(jieqi_dates, jieqi_dates[1:]):
        month_days = [d for d in day_klines if month_start <= d.date < month_end]
        if month_days:
            monthly_bars.append({
                'open': month_days[0].open,
                'close': month_days[-1].close,
                'high': max(d.high for d in month_days),
                'low': min(d.low for d in month_days),
                'volume': sum(d.volume for d in month_days),
                'label': f'{lunar_month_name}',  # 如"卯月"
            })
    return monthly_bars
```

### 7.2 坐标轴标注

- 日K横轴：公历日期 + 月柱/日柱（如"丙午年 辛卯月 甲子日"）
- 月K横轴：农历月名（寅月、卯月...）
- 年K横轴：干支年（丙午、丁未...）

**设计决策**：同时显示农历月名 + 公历日期范围，如"卯月(3/5-4/5)"，方便用户对照公历。

## 九、数据更新策略

（来自 `.C4股票关联.txt` 第1条、`股票-卦例显示规则.md` 第9条）

| 策略 | 说明 |
|------|------|
| 首次添加 | 用户在弹窗中指定日期范围（起始→截止），按需获取 |
| 手动更新 | 用户在管理列表点击[更新数据]，获取最新数据追加 |
| 不自动更新 | 不在后台自动请求数据，节约资源 |
| 缓存机制 | 数据存入本地数据库，不重复获取已有日期 |

**增量更新逻辑**：

```
1. 查询 stock_day_kline 表中该标的的最大 trade_date
2. 从该日期次日开始，通过 AKShare 获取到最新的日K数据
3. 追加到 stock_day_kline 表（INSERT IGNORE 避免重复）
4. 同理更新 stock_minute_kline
```

**错误处理**：获取数据失败时返回错误信息，前端显示提示让用户自行处理。

## 十、占验情况联动

在卦例浮窗中修改占验情况后：
- K线图的对应K线样式应立即更新（应验→实心，模糊/不验→空心+灰底）
- 占验情况作为独立标签存储（如"占验-应验"、"占验-模糊"、"占验-不验"），修改后直接更新 guali_tag 表，C1通过数据库自然同步

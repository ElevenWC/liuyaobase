## 一、模块概述

### 1.1 模块定位

C4股票关联模块将股票K线图与卦例系统关联起来，使用户可以在查看走势图的同时看到对应日期的卦例。

**当前版本聚焦**：先做股票，期货暂缓（见 §六）。

### 1.2 核心数据流

```
用户搜索股票名称 → AKShare获取历史数据 → 存入本地数据库
                                                  ↓
                                    绘制K线图（日K/月K/年）
                                                  ↓
用户点击K线 → 通过标签查找对应卦例 → 弹出卦例详情浮窗 + 分时图浮窗
```

### 1.3 数据来源

| 数据类型 | 来源 | 存储位置 | 更新方式 |
|---------|------|---------|---------|
| 股票历史数据 | AKShare API | stock_day_kline / stock_minute_kline（分钟K OHLC） | 用户手动触发更新 |
| 卦例数据 | 系统已有 | guali 表 + guali_* 扩展表 | 已通过C1导入 |

### 3.1 整体布局

```

│  [返回]  000503 ST生物                                       [设置]       │

│                                                                          │
│  ┌────────────────────────────────────────────────────────────────────┐  │
│  │                                                                    │  │
│  │                      K线图主区域（ECharts）                        │  │
│  │                                                                    │  │
│  │  横轴：公历日期（日K）+ 月柱日柱                                    │  │
│  │  纵轴：价格                                                        │  │
│  │  成交量副图                                                        │  │
│  │                                                                    │  │
│  │  图例：                                                            │  │
│  │  □ 空心K线  = 无卦例                                               │  │
│  │  ■ 实心K线  = 有卦例（应验）                                       │  │
│  │  ▣ 空心+灰底 = 有卦例（模糊/不验）                                 │  │
│  │                                                                    │  │
│  └────────────────────────────────────────────────────────────────────┘  │
│                                                                          │
│  该标的关联卦例数：24 条                                                  │
│                                                                          │
└──────────────────────────────────────────────────────────────────────────┘
```

**设计要点**：
- K线图横轴除了公历时间外，还需要显示**月柱、日柱**标志（来自 `guali_time` 表）
- 日K图中双击某根K线 → 弹出分时图浮窗 + 卦例浮窗
- K线有三种显示形式（见 3.3 节）

### 3.2 K线周期切换

切换K线周期时，数据聚合方式不同：

| 周期 | 股票数据来源 | 卦例匹配方式 |
|------|------------|------------|
| 日K | stock_day_kline 表 | 日期精确匹配 |
| 月K | stock_day_kline 聚合 | **农历月**聚合（节气→节气） |
| 年K | stock_day_kline 聚合 | **农历年**聚合 |

**关键设计**：
- 月K和年K都是农历月/年，而非公历年月
- 需要根据节气来聚合（如卯月 = 惊蛰→清明）
- 节气日期通过 B1 核心算法模块的 `get_jieqi_dates(year)` 函数获取（详见 §七）

### 3.3 K线三种样式

| 类型 | 条件 | 阳线（涨） | 阴线（跌） |
|------|------|----------|----------|
| 普通K线 | 该日无卦例 | 空心红色 | 空心绿色 |
| 应验K线 | 有卦例 + 占验=应验 | **实心**红色 | **实心**绿色 |
| 待验K线 | 有卦例 + 占验=模糊/不验 | 空心红色+**灰色填充** | 空心绿色+**灰色填充** |

## 四、卦例浮窗

### 4.1 浮窗总体设计

卦例浮窗复用 C1 的标准显示，使用共享组件。卦爻辞浮窗使用共享 `GuaCiFloat.vue` 组件（位于 `frontend/src/components/shared/GuaCiFloat.vue`，供C1/C2/C3/C4共用）。

### 4.2 日卦、月卦、年卦的区分

**核心概念**：卦例按其占问的时间范围分为三种类型，对应不同的K线周期：

| 卦例类型 | 占问内容示例 | 对应K线周期 | 匹配方式 |
|---------|------------|:----------:|---------|
| 日卦 | "ST生物今日走势"、"橡胶02.25夜盘" | 日K | 占问日期 = K线日期 |
| 月卦 | "ST生物卯月走势"、"橡胶本月行情" | 月K | 占问农历月 = K线农历月 |
| 年卦 | "ST生物丙午年走势" | 年K | 占问农历年 = K线农历年 |

**区分方式**：通过**标签**来标记卦例的类型。

```
标签结构（方案B：卦例同时打两个标签）：
├── 标的标签：股票-ST生物
└── 类型标签：日卦 / 月卦 / 年卦（独立标签）
```

一个卦例打上两个标签即完成分类，C4根据类型标签筛选对应的卦。

### 4.3 日K点击 → 双浮窗

双击某根日K线后，弹出两个浮窗（与月K/年K不同，日K只显示**日卦**）：

```

│   分时图浮窗    │     │      卦例详情浮窗          │

│  2026-02-25    │     │  本卦：天火同人             │
│  开盘：XX      │     │  之卦：风火家人             │
│  收盘：XX      │     │  （完整卦象显示，同C1）     │
│  最高：XX      │     │                            │
│  最低：XX      │     │  六神 六亲 地支 世应 卦象  │
│  成交量：XX    │     │  玄武 兄弟 戌土      ───   │
│                │     │  ...                       │
│  [分时曲线图]  │     │                            │
│                │     │  [卦爻辞] [修改占验]       │
```

**设计要点**：
- 卦例详情浮窗展现完整的卦象信息，与C1完全一致
- 浮动窗口可自由移动、多开
- 浮窗右上角有**天干显示开关**（独立控制，默认关闭，不影响C1详情页的开关设置）
- 点击卦名使用共享 GuaCiFloat.vue 弹出卦爻辞浮窗
- 浮窗中有[修改占验]按钮（见 §十）
- 若当日有多个日卦，每个卦例弹出独立的浮窗
- 若当日无日卦，浮窗显示"该日无对应卦例"

**浮窗数据来源（5张表，与C1完全一致）**：

| 表名 | C4浮窗用途 |
|------|-----------|

| guali_gua | 卦宫、宫位、特殊类型、反吟伏吟 |

C4浮窗的显示内容与C1完全一致，数据查询直接复用C1的5表查询逻辑。

### 4.4 月K点击 → 月卦浮窗

切换到月K后，点击某月K线：
- 弹出该**农历月**对应的**月卦**（占当月走势的卦例，通常只有一卦）
- 如果该月没有月卦，显示"该月无对应卦例"

### 4.5 年卦显示

在月K线的横轴坐标上显示**年份标签**：
- 点击年份标签 → 弹出该农历年对应的**年卦**
- 如果该年没有年卦，显示"该年无对应卦例"

## 五、标签关联机制

### 5.1 卦例与标的的关联方式

**方案**：通过标签系统关联。

```
标签结构（方案B：卦例同时打两个标签）：
├── 标的标签（关联 stock_info.tag_id）
│   ├── 股票-ST生物
│   └── 股票-指南针
└── 类型标签（独立标签，与标的标签并列）
    ├── 日卦（默认）
    ├── 月卦
    └── 年卦
```

一个卦例同时打两个标签：标的标签（如"股票-ST生物"）+ 类型标签（如"月卦"）。C4查询时通过两个标签联合过滤。

**关联流程**：
1. 用户创建股票标的时，自动创建对应二级标签（或在已有标签中选择）
2. 在C1卦例管理界面，用户可为卦例打上标签（如"ST生物"）
3. C4界面中，根据当前查看的标的找到关联标签，再通过 `guali_tag` 表找到所有关联卦例
4. 将这些卦例按日期组织成"卦例池"，与K线日期匹配

**数据查询路径**：
```
stock_info.tag_id → tag表 → guali_tag表 → guali表 → 卦例池
```

### 5.2 关联方式确认：仅使用标签匹配

**最终决定**：仅使用**标签匹配**方式，不自动通过占问事由搜索。

用户需要手动为卦例打上标的标签（如"ST生物"）+ 卦类型标签（如"日卦"/"月卦"/"年卦"）。

**需要的功能支撑**：

| 功能 | 所属模块 | 说明 |
|------|:------:|------|
| 创建标签（二级结构） | C1 | 已设计，如"股票-ST生物" |
| 单个卦例打标签 | C1 | 已设计，卦例详情页点击标签区域 |
| **批量打标签** | **C3** | C3复杂检索模块实现：用户检索出一批卦例后，多选并批量添加标签。C4依赖此功能 |

> **注意**：批量打标签归属C3模块实现（审查决议C4-1）。C4启动前需确保C3的批量打标签功能已可用。单个卦例打标签继续由C1负责。

## 六、期货特殊处理

> **状态：暂缓** — 经审查决议C4-5，期货功能暂时不做。先集中精力实现股票功能。
> 本节内容保留作为未来参考，但当前版本(v3.0)不包括期货相关开发工作。
> 期货表已重设计为2张（futures_info + futures_minute_kline），日K不存表由分钟K实时聚合。

### 6.1 期货与股票的关键差异

| 特性 | 股票 | 期货 |
|------|------|------|
| 交易时段 | 9:30-11:30, 13:00-15:00 | 含夜盘（21:00-次日凌晨） |
| 日K定义 | 自然日 | 前一天夜盘+当天日盘 |
| 主力合约 | 不存在 | 需要跟踪主力合约切换 |
| 数据粒度 | 日K + 分时 | 分时段 → 聚合为日K |
| 夜盘归属 | 不存在 | 夜盘归入下一交易日，但占卜不按此计算 |

### 6.2 期货夜盘分类

| 类型 | 夜盘时间 | 典型品种 | 日K聚合方式 |
|------|---------|---------|------------|
| 无夜盘 | — | 部分农产品 | 日盘数据直接作为日K |
| 短夜盘 | 21:00-23:00 | 橡胶、螺纹钢 | 夜盘+次日日盘 = 一根日K |
| 长夜盘 | 21:00-次日02:30 | 黄金、白银、原油 | 夜盘+次日日盘 = 一根日K |

**设计决策**：不区分长短夜盘，统一将日盘+夜盘聚合为一根日K。使用自定义聚合逻辑（不能用标准的"自然日"聚合方式）。

### 6.3 主力合约切换

期货存在主力合约切换问题。例如橡胶从 ru2505 切换到 ru2509 时，K线图需要连续显示。

**设计决策**：使用 AKShare 的"主力连续"合约数据（如 ru888），K线图数据天然连续，无需手动处理合约切换。

## 七、农历月K/年K聚合

### 7.1 聚合规则

月K和年K必须按**农历（节气）**而非公历聚合：

| 农历月 | 节气范围 | 示例（2026年） |
|--------|---------|---------------|
| 寅月 | 立春→惊蛰 | 2月4日→3月5日 |
| 卯月 | 惊蛰→清明 | 3月5日→4月5日 |
| 辰月 | 清明→立夏 | 4月5日→5月5日 |
| ... | ... | ... |

**月K聚合算法**：
```python
def aggregate_monthly_kline(day_klines: list, jieqi_dates: list) -> list:
    """
    将日K数据按节气范围聚合为农历月K
    - day_klines: 日K数据列表
    - jieqi_dates: 节气日期列表（来自 B1 模块提供）
    - 返回: 月K数据列表（开、高、低、收、成交量）
    """
    monthly_bars = []
    for month_start, month_end in zip(jieqi_dates, jieqi_dates[1:]):
        month_days = [d for d in day_klines if month_start <= d.date < month_end]
        if month_days:
            monthly_bars.append({
                'open': month_days[0].open,
                'close': month_days[-1].close,
                'high': max(d.high for d in month_days),
                'low': min(d.low for d in month_days),
                'volume': sum(d.volume for d in month_days),
                'label': f'{lunar_month_name}',  # 如"卯月"
            })
    return monthly_bars
```

**节气数据来源**：节气日期列表通过 B1 核心算法模块的 `get_jieqi_dates(year)` 函数获取（详见 `.B核心算法.md` B1.6 节）。该函数返回指定年份所有节气的公历日期，C4 的月K/年K聚合服务直接调用此函数，不自行实现节气计算逻辑。

### 7.2 坐标轴标注

- 日K横轴：公历日期 + 月柱/日柱（如"丙午年 辛卯月 甲子日"）
- 月K横轴：农历月名（寅月、卯月...）
- 年K横轴：干支年（丙午、丁未...）

**设计决策**：同时显示农历月名 + 公历日期范围，如"卯月(3/5-4/5)"，方便用户对照公历。

## 八、多标的对比查看

支持同时查看多个股票的K线图，便于对比分析。

**实现方式**：使用**浏览器标签页**（浏览器原生Tab），每个标的在独立的浏览器标签页中打开。
- 不需要 `window.open()` 或前端多窗组件
- 用户通过浏览器自身的标签页管理即可切换、对比
- 每个标签页独立加载该标的的数据，互不干扰

> 经审查决议C4-10：暂不需要前端多窗组件，浏览器标签页足够。

## 九、数据更新策略

| 策略 | 说明 |
|------|------|
| 首次添加 | 用户在弹窗中指定日期范围（起始→截止），按需获取 |
| 手动更新 | 用户在管理列表点击[更新数据]，获取最新数据追加 |
| 不自动更新 | 不在后台自动请求数据，节约资源 |
| 缓存机制 | 数据存入本地数据库，不重复获取已有日期 |

**增量更新逻辑**：

```
1. 查询 stock_day_kline 表中该标的的最大 trade_date
2. 从该日期次日开始，通过 AKShare 获取到最新的日K数据
3. 追加到 stock_day_kline 表（INSERT IGNORE 避免重复）
4. 同理更新 stock_minute_kline
```

**为何使用 MAX(trade_date) 而非 system_config**：

| 方案 | 说明 |
|------|------|
| MAX(trade_date) ✅ | 查询 stock_day_kline 表中该标的的最大日期，按标的分开管理 |
| system_config ❌ | 全局配置表记录"最后更新时间"，但不同标的更新频率不同 |

**理由**：
- C4 共有多个股票标的，各标的的更新频率不同（有的每天关注，有的偶尔查看）
- 使用全局 system_config 会导致：更新标的A后，标的B的"最后更新"也被覆盖
- MAX(trade_date) 按标的分开记录，每个标的独立维护自己的最新日期
- 与 C1 的 JSON 导入场景不同：C1 只有一个数据源（一个JSON文件），使用 system_config 合理；C4 有多个数据源（多个股票），每个独立管理更合理

**AKShare 限流处理**：

AKShare API 调用需要限流，避免 IP 被封：
- 最大请求频率：**1次/2秒**（0.5 QPS）
- 实现方式：在 `StockService` 中使用 `asyncio.sleep(2)` 或令牌桶算法
- 首次添加标的时批量获取历史数据，后续更新只获取新增日期

**错误处理**：获取数据失败时返回错误信息，前端显示提示让用户自行处理。

## 十、占验情况联动（标签化存储）

### 10.1 核心原则

占验情况 = 标签。修改占验 = 修改 guali_tag 关联。

> 经审查决议C4-3：占验和卦例表中的其他属性相去甚远，并且夹杂了人的判断，不适合放到卦例表中。使用标签方式存储，由用户自己管理和修改。

### 10.2 存储方式

占验情况不作为 guali 表的独立字段，而是作为**标签**存储：

| 占验结果 | 标签名 | 存储位置 |
|---------|--------|---------|
| 应验 | 占验-应验 | guali_tag 表（guali_id + tag_id） |
| 模糊 | 占验-模糊 | guali_tag 表 |
| 不验 | 占验-不验 | guali_tag 表 |
| 未判定 | （无标签） | -- |

标签系统中有三种不同语义的标签并存：

| 标签类别 | 示例 | 用途 |
|---------|------|------|
| 分类标签 | "股票-ST生物" | 卦例分类，供C4筛选标的 |
| 类型标签 | "日卦"、"月卦"、"年卦" | C4周期匹配 |
| 状态标签 | "占验-应验"、"占验-模糊"、"占验-不验" | 占验情况 |

前端标签选择器应区分这三种类别（如在标签列表中用不同图标或颜色标识），避免用户混淆。占验标签互斥（同一时刻每个卦例只能有一个占验状态），前端需保证选择新占验时自动移除旧占验标签。

### 10.3 C4浮窗修改占验的流程

1. 用户在C4卦例浮窗点击[修改占验]
2. 弹出占验选择器（应验/模糊/不验）
3. 后端执行：`DELETE FROM guali_tag WHERE guali_id=X AND tag_id IN (占验标签的tag_id列表)`
4. 后端执行：`INSERT INTO guali_tag (guali_id, tag_id) VALUES (X, 用户选择的tag_id)`

### 10.4 联动效果

修改占验标签后：
- K线图对应K线样式立即更新（应验 → 实心K线，模糊/不验 → 空心+灰底K线）
- C1模块自动同步（因为都查 guali_tag 表，无需额外通知）

### 12.1 股票模块依赖（当前版本v3.0）

| 表名 | 用途 | 状态 |
|------|------|:----:|
| stock_info | 股票基本信息 | ✅ 已设计 |
| stock_day_kline | 股票日K数据 | ✅ 已设计 |

| guali | 卦例主表 | ✅ 共用C1 |
| guali_time | 卦例时间扩展表（干支、旬空） | ✅ 共用C1 |
| guali_yao | 卦例爻扩展表（浮窗显示核心表） | ✅ 共用C1 |
| guali_shensha | 卦例神煞扩展表（浮窗显示用） | ✅ 共用C1 |
| guali_gua | 卦例卦类扩展表（浮窗显示用） | ✅ 共用C1 |
| guali_tag | 卦例-标签关联（核心关联桥梁） | ✅ 共用C1 |
| tag | 标签表（含标的、类型、占验三类标签） | ✅ 共用C1 |

**C4浮窗查询只需5张表（与C1完全一致）**：
1. `guali` — 基本信息（占问时间、事由、占断）
2. `guali_time` — 时间干支
3. **`guali_yao`** — 全部爻数据（六神、六亲、地支天干、世应、伏神、动爻暗动）
4. `guali_shensha` — 神煞地支值
5. `guali_gua` — 卦宫、宫位、特殊类型、反伏状态

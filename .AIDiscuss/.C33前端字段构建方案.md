## 一、设计原则

### 1.1 核心流程

```
┌─────────────────────────────────────────────────────────────────────┐
│                           用户交互层                                 │
│   用户通过拖拽/点击方式，从字段库选择字段，构建检索条件              │
└─────────────────────────────────────────────────────────────────────┘
                                  │
                                  ▼
┌─────────────────────────────────────────────────────────────────────┐
│                          状态管理层 (Pinia)                          │
│   conditions: [{id, field, operator, value, scope?}]               │
│   logicChain: [{type, id?, value?}]                                │
└─────────────────────────────────────────────────────────────────────┘
                                  │
                                  ▼
┌─────────────────────────────────────────────────────────────────────┐
│                          API 请求层                                  │
│   POST /api/v3/search                                               │
│   Body: { conditions, logic, pagination }                           │
└─────────────────────────────────────────────────────────────────────┘
                                  │
                                  ▼
┌─────────────────────────────────────────────────────────────────────┐
│                        后端 SQL 构建层                               │
│   1. 字段名 → 数据库字段映射                                        │
│   2. 复合字段 → 拆解为实际字段 + scope_filter                       │
│   3. 关系字段 → 调用核心算法计算                                    │
│   4. 生成 SQL + 执行查询                                            │
└─────────────────────────────────────────────────────────────────────┘
```

### 1.2 字段抽象层

**关键概念**：前端显示的字段名是**用户友好**的抽象概念，后端通过映射配置转换为实际的数据库字段。

| 前端字段名      | 类型 | 数据库映射 |
|------------|------|-----------|
| `公历年`      | 简单字段 | `YEAR(g.zhanwen_time)` |
| `六亲`       | 爻类字段 | `guali_yao.ben_liuqin`（需配合条件组指定来源） |
| `妻财爻长生于月支` | 关系字段 | 核心算法计算地支关系 |

**条件组的作用**：
- 同一爻条件组：通过"适用范围"多选来指定多个来源（OR逻辑）
- 同爻位条件组：通过分来源条件来指定每个来源的要求（AND逻辑）

## 二、字段分类与输入方式

### 2.0 字段与条件组支持情况

| 字段类别 | 支持条件组 | 说明 |
|---------|-----------|------|
| **时间类字段** | ❌ 不支持 | 卦例级别，与爻无关，直接作为独立条件使用 |
| **卦类字段** | ❌ 不支持 | 卦例级别，与爻无关，直接作为独立条件使用 |
| **标签类字段** | ❌ 不支持 | 卦例级别，与爻无关，直接作为筛选条件使用 |
| **爻属性字段** | ✅ 支持 | 有5种来源，**必须在条件组内使用** |
| **关系字段** | ⚠️ 特殊 | 可**引用**条件组的结果，或直接使用爻对象 |
| **神煞字段** | ⚠️ 特殊 | 类似关系字段，判断某地支是否为/带某神煞 |
| **数目判断** | ❌ 不支持 | 卦级别，判断某属性在卦中的数目 |

**详细说明**：

#### ❌ 不支持条件组的字段（直接使用）

| 字段类型 | 具体字段 | 输入方式 |
|---------|---------|---------|
| 时间类 | 公历年、月柱、月支、日柱、日干、日支、旬空 | 手动输入/下拉选择 |
| 卦类 | 本卦名、之卦名、本卦卦宫、本卦宫位、本卦特殊类型、反吟、伏吟 | 手动输入/下拉选择 |
| 标签类 | 股票、占验情况等 | 复选框多选 |

#### ✅ 支持条件组的字段（必须在条件组内）

| 字段类型 | 具体字段 | 来源选项 |
|---------|---------|---------|
| 爻位 | 初爻~上爻 | 5种来源通用 |
| 爻类型 | 阳爻/阴爻 | 5种来源通用 |
| 爻状态 | 动爻/静爻 | 本卦、变爻、之卦(静爻) |
| 暗动 | 是/否 | 本卦 |
| 六亲 | 父母官鬼子孙妻财兄弟 | 5种来源通用 |
| 天干 | 甲乙丙丁戊己庚辛壬癸 | 本卦、变爻、之卦(静爻) |
| 地支 | 子丑寅卯... | 5种来源通用 |
| 六神 | 青龙朱雀勾陈螣蛇白虎玄武 | 5种来源通用（六神是爻位特征） |
| 世应 | 世爻/应爻/无 | 本卦、变爻、之卦(静爻) |
| 伏神存在 | 有/无 | 仅增删伏神来源 |
| 神煞 | 干禄、驿马、羊刃、桃花 | 独立条件格式 |

#### ⚠️ 关系字段（特殊处理）

关系字段有两种使用方式：

1. **直接使用爻对象**：`[妻财爻] [生] [世爻]`
2. **引用条件组**：`[条件组A的爻] [墓] [于] [日支]`

详见第四章"关系字段引用条件组"部分。

#### ⚠️ 神煞字段（类似关系字段）

神煞字段判断某地支是否为/带某神煞，交互方式类似关系字段：

```
[某地支] [是/带/是或带] [某神煞]

例如：
[妻财爻] [是] [干禄]        含义：妻财爻的地支是干禄
[月支] [带] [驿马]           含义：月支带驿马（即驿马星落在月支上）
[条件组A的爻] [是或带] [桃花] 含义：条件组A筛选出的爻，其地支是或带桃花
```

**神煞列表**：干禄、驿马、羊刃、桃花

**注意**：神煞是地支的属性，所以只要是有地支的对象都可以判断神煞：
- 五种来源的爻（本卦、变爻、之卦静爻、易冒伏神、增删伏神）
- 时间对象（年支、月支、日支）

#### ❌ 数目判断（卦级别，独立使用）

数目判断是卦级别的功能，用于判断某属性在卦中的数量：

```
[本卦] 中 [六亲=妻财] 的数目 [=] [0]    含义：本卦中没有妻财爻
[本卦] 中 [爻状态=动爻] 的数目 [>] [2]  含义：本卦中动爻超过2个
```

详见附录C"数目判断设计"。

### 2.1 概述：三种条件组

**已确认**（Q13）：检索条件通过**条件组**来组织，有三种类型

| 条件组类型 | 核心约束 | 多选来源逻辑 | 爻位指定位置 |
|-----------|---------|-------------|-------------|
| **同一爻条件组** | 同一**来源**的爻 | OR（满足任一即可） | 可以在条件组内 |
| **同爻位条件组** | 同一**爻位** | AND（必须同一爻位） | 只能在条件组外 |
| **飞神条件组** | 本卦中与伏神同爻位的爻 | 返回所有飞神 | 用神六亲指定 |

**注意**：飞神条件组是一种特殊的条件组，详情见3.5节。

### 2.2 五种爻来源

**已确认**（Q13）：所有爻类字段都来自以下5种来源

| 来源 | 说明 | 数据库字段前缀 | 示例字段 |
|------|------|---------------|---------|
| **本卦** | 本卦的6个爻 | `ben_*` | ben_liuqin, ben_dizhi, ben_tiangan |
| **变爻** | 动爻变化后的爻 | `zhi_*` + `is_dong=TRUE` | zhi_liuqin, zhi_dizhi |
| **之卦(静爻)** | 之卦中未变化的爻 | `zhi_*` + `is_dong=FALSE` | zhi_liuqin, zhi_dizhi |
| **易冒伏神** | 每爻位的易冒伏神 | `yimao_*` | yimao_liuqin, yimao_dizhi |
| **增删伏神** | 有伏神的卦位 | `zengshan_*` | zengshan_liuqin, zengshan_dizhi |

**注意**：如果本卦没有动爻（爻变代码=000000），则之卦不存在，"变爻"和"之卦(静爻)"来源的相关字段均为NULL。

| 字段名 | 输入方式 | 值来源 | 可用来源 | 说明            |

| 爻类型 | 下拉选择 | 阳爻/阴爻 | 本卦、变爻、之卦(静爻) | **伏神不适用于爻类型** |

| 暗动 | 下拉选择 | 是/否 | 仅本卦 |               |
| 六亲 | 下拉选择 | 父母官鬼子孙妻财兄弟 | 5种来源通用 |               |
| 天干 | 下拉选择 | 甲乙丙丁戊己庚辛壬癸 | 本卦、变爻、之卦(静爻) | 伏神没有天干        |
| 地支 | 下拉选择 | 子丑寅卯辰巳午未申酉戌亥 | 5种来源通用 |               |
| 六神 | 下拉选择 | 青龙朱雀勾陈螣蛇白虎玄武 | 5种来源通用 | 六神是爻位特征       |
| 世应 | 下拉选择 | 世爻/应爻/无 | 本卦、变爻、之卦(静爻) | 伏神没有世应        |

**爻类型说明**：
- **本卦的爻类型**：根据本卦代码确定（1=阳爻，0=阴爻）
- **变爻的爻类型**：根据之卦代码确定（动爻变化后的新类型）
- **之卦(静爻)的爻类型**：根据之卦代码确定
- **伏神**：伏神本身没有爻类型属性，不适用于爻类型字段

### 2.6 神煞类字段

**特点**：可以配合任意条件组使用

**核心概念**：
- 神煞是**地支的神煞**，不是爻的神煞
- 只要有地支的对象都可以判断神煞（5种来源的爻 + 时间对象）
- **"是"**：该地支本身就是某神煞所在的地支
- **"带"**：该地支与神煞地支有**相冲或相合**关系（神煞传播规则：与神煞地支相冲或相合的地支也"带"该神煞）

**交互格式**（统一使用三选项格式）：

```
┌─────────────────────────────────────────────┐
│ [某地支 ▼] [是 ▼] [干禄 ▼]            [×]   │
└─────────────────────────────────────────────┘

第二个下拉选项：
  - 是：该地支本身就是某神煞所在的地支
  - 带：该地支与神煞地支有相冲或相合关系
  - 是或带：两者皆可
```

| 字段名 | 输入方式 | 值来源 |
|--------|---------|--------|
| 干禄 | 下拉选择 | [某地支 ▼] [是/带/是或带 ▼] [干禄] |
| 驿马 | 下拉选择 | [某地支 ▼] [是/带/是或带 ▼] [驿马] |
| 羊刃 | 下拉选择 | [某地支 ▼] [是/带/是或带 ▼] [羊刃] |
| 桃花 | 下拉选择 | [某地支 ▼] [是/带/是或带 ▼] [桃花] |

**神煞列表**：

| 神煞 | 说明 |
|-----|------|
| 干禄 | 日干禄位 |
| 驿马 | 日支驿马位 |
| 羊刃 | 日干羊刃位 |
| 桃花 | 日支桃花位 |

**注意**：神煞是地支的属性，所有有地支的对象都可以判断神煞（包括年月日支）。

### 2.7 条件组交互示例

#### 同一爻条件组

```
┌─────────────────────────────────────────────────────────┐
│ 同一爻条件组 【满足任一来源即可】                    [×]   │
│ ┌─────────────────────────────────────────────────────┐ │
│ │ 适用范围（可多选）:                                  │ │
│ │ ☑本卦 ☑增删伏神 ☐变爻 ☐之卦(静爻) ☐易冒伏神       │ │
│ ├─────────────────────────────────────────────────────┤ │
│ │ 条件:                                               │ │
│ │ [爻位] [=] [初爻] AND [六亲] [=] [妻财] AND [暗动] [=] [是] │
│ └─────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────┘
```

**含义**：查找"本卦初爻是妻财且暗动"**或**"增删伏神初爻是妻财且暗动"的卦例

#### 同爻位条件组

```
┌─────────────────────────────────────────────────────────┐
│ 爻位筛选：[第3爻] ← 在条件组外指定                        │
├─────────────────────────────────────────────────────────┤
│ 同爻位条件组 【必须同一爻位】                        [×]   │
│ ┌─────────────────────────────────────────────────────┐ │
│ │ ☐易冒伏神                                          │ │
│ │ ☑增删伏神    [六亲] [=] [官鬼]              [×]   │ │
│ │ ☑本卦        [世应] [=] [世爻] AND [暗动] [=] [是] │ │
│ │ ☑变爻        [六亲] [=] [妻财]              [×]   │ │
│ │ ☐之卦(静爻)                                        │ │
│ └─────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────┘
```

**含义**：查找"第3爻"上同时满足以下条件的卦例：
- 增删伏神六亲=官鬼
- 本卦世应=世爻且暗动=是
- 变爻六亲=妻财

## 三、条件组设计

### 3.1 三种条件组的本质区别

**已确认**（Q13）：需要保留三种条件组，它们不能互相替代

| 条件组类型 | 核心约束 | 多选来源逻辑 | 爻位指定位置 | 本质 |
|-----------|---------|-------------|-------------|------|
| **同一爻条件组** | 同一**来源**的爻 | **OR**（满足任一来源即可） | 可以在条件组内 | 宽松匹配 |
| **同爻位条件组** | 同一**爻位** | **AND**（必须同一爻位） | **只能**在条件组外 | 严格匹配 |
| **飞神条件组** | 本卦中与伏神同爻位的爻 | 返回所有飞神 | 用神六亲指定 | 特殊条件组 |

**注意**：
1. 飞神条件组是一种特殊的条件组，详情见3.5节
2. 后端优化：预存表应存放**六十四卦的代码**而非卦例ID，因为本卦代码决定了其会不会缺少某六亲，检索卦例时直接对比判断即可

### 3.2 同一爻条件组

**适用场景**：查找"多个来源中任一满足"的爻

**特点**：
- 适用范围可多选，选中多个来源时用 **OR** 连接
- 爻位可以在条件组内指定
- 适用于"只关心某个爻的属性，不关心爻位"的场景

**交互设计**：
```
┌─────────────────────────────────────────────────────────┐
│ 同一爻条件组（满足任一来源即可）                    [×]   │
│ ┌─────────────────────────────────────────────────────┐ │
│ │ 适用范围（可多选）:                                  │ │
│ │ ☑本卦 ☑增删伏神 ☐变爻 ☐之卦(静爻) ☐易冒伏神       │ │
│ ├─────────────────────────────────────────────────────┤ │
│ │ 条件:                                               │ │
│ │ [六亲] [=] [妻财] AND [地支] [=] [午]        [×]   │ │
│ └─────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────┘
```

**SQL生成**（多选来源 = OR）：
```sql
SELECT DISTINCT g.*
FROM guali g
JOIN guali_yao y ON g.id = y.guali_id
WHERE (y.ben_liuqin = '妻财' AND y.ben_dizhi = '午')           -- 本卦
   OR (y.zengshan_liuqin = '妻财' AND y.zengshan_dizhi = '午'); -- 增删伏神
```

### 3.3 同爻位条件组

**适用场景**：查找"同一爻位上多个来源之间的关系"

**特点**：
- 各来源之间用 **AND** 连接（必须同时满足）
- 爻位**只能**在条件组外指定
- 适用于"飞神克伏神"、"变爻生本卦"等需要同一爻位的场景

**交互设计**：
```
┌─────────────────────────────────────────────────────────┐
│ 爻位筛选：[第3爻] ← 必须在条件组外指定                    │

## 四、关系类字段设计

### 4.1 核心原则：地支关系

**已确认**（U3）：关系类字段**本质上处理的是地支之间的关系**

```
[妻财爻][生][世爻]
    ↓ 翻译为地支
妻财爻.地支（如巳-火） 生 世爻.地支（如未-土）
    ↓ 判断五行关系
火生土 → 成立
```

**实现步骤**：
1. **确定地支**：根据爻对象找到对应的 `*_dizhi` 字段
2. **调用核心算法**：判断地支之间的五行关系

### 4.2 关系类型汇总

| 关系类型 | 关系名称 | 顺序性 | 是否有"于"字 | 说明 |
|---------|---------|-------|-------------|------|
| **五行生克** | 生 | 有顺序 | 无 | 对象1地支五行 → 对象2地支五行 |
| | 克 | 有顺序 | 无 | 对象1地支五行 → 对象2地支五行 |
| **地支合冲** | 相合 | 无顺序 | 无 | 两个地支相合（A合B = B合A） |
| | 相冲 | 无顺序 | 无 | 两个地支相冲（A冲B = B冲A） |
| | 半合 | 无顺序 | 无 | 两个地支半合 |
| | 三合 | 无顺序 | 无 | 三个地支形成三合局 |
| **地支相同** | = | 无顺序 | 无 | 两个地支相同 |
| **生旺墓绝** | 长生/帝旺/墓/绝 | 有顺序 | **有** | 对象1地支的长生位 = 对象2地支 |

### 4.3 地支获取映射表

| 爻对象 | 地支字段 | 说明 |

### 4.4 核心算法函数

```python
# 五行生克（有顺序）
def check_sheng(dizhi1, dizhi2):
    """判断地支1的五行是否生地支2的五行"""
    wuxing1 = get_wuxing(dizhi1)  # 如：巳→火
    wuxing2 = get_wuxing(dizhi2)  # 如：未→土
    return WUXING_SHENG[wuxing1] == wuxing2  # 火生土？

def check_ke(dizhi1, dizhi2):
    """判断地支1的五行是否克地支2的五行"""
    wuxing1 = get_wuxing(dizhi1)
    wuxing2 = get_wuxing(dizhi2)
    return WUXING_KE[wuxing1] == wuxing2

# 地支合冲（无顺序）
def check_he(dizhi1, dizhi2):
    """判断两个地支是否相合"""
    return (dizhi1, dizhi2) in LIUHE or (dizhi2, dizhi1) in LIUHE

def check_chong(dizhi1, dizhi2):
    """判断两个地支是否相冲"""
    return (dizhi1, dizhi2) in LIUCHONG or (dizhi2, dizhi1) in LIUCHONG

def check_banhe(dizhi1, dizhi2):
    """判断两个地支是否半合"""
    return (dizhi1, dizhi2) in BANHE or (dizhi2, dizhi1) in BANHE

# 地支相同（无顺序）
def check_same(dizhi1, dizhi2):
    """判断两个地支是否相同"""
    return dizhi1 == dizhi2

# 生旺墓绝（有顺序）
def check_shengwang(dizhi1, dizhi2, relation):
    """判断地支1相对于地支2的生旺墓绝关系"""
    wuxing = get_wuxing(dizhi1)
    target = SHENGWANG_TABLE[wuxing][relation]  # 如：火的长生=寅
    return dizhi2 == target
```

### 4.5 交互设计

**统一格式说明**：
- 生克合冲关系：`[地支1] [关系] [地支2]`（无"于"字）
- 生旺墓绝关系：`[地支1] [关系] [于] [地支2]`（有"于"字）
- 地支相同：`[地支1] [=] [地支2]`

**生克关系**（有顺序，无"于"字）：
```
┌─────────────────────────────────────────────┐
│ [妻财爻 ▼] [生 ▼] [世爻 ▼]            [×]   │
└─────────────────────────────────────────────┘
含义：妻财爻.地支(五行) 生 世爻.地支(五行)
```

**合冲/半合关系**（无顺序，无"于"字，2个地支对象）：
```
┌─────────────────────────────────────────────┐
│ [妻财爻 ▼] [相合 ▼] [月支 ▼]          [×]   │
└─────────────────────────────────────────────┘
含义：妻财爻.地支 与 月支 的关系
关系下拉选项：[相合] [相冲] [半合]
```
半合与相合/相冲共用同一交互模板——2个地支选择器 + 1个关系下拉。关系下拉除"相合""相冲"外多一个"半合"选项，后端调用 `check_banhe()` 函数。

**生旺墓绝**（有顺序，使用"于"字）：
```
┌─────────────────────────────────────────────┐
│ [妻财爻 ▼] [长生 ▼] [于 ▼] [月支 ▼]  [×]   │
└─────────────────────────────────────────────┘
含义：妻财爻.地支 的长生位是 月支
例如：妻财爻是巳火，长生在寅，所以查找月支=寅的卦例
```

**地支相同**（无顺序，无"于"字）：
```
┌─────────────────────────────────────────────┐
│ [妻财爻 ▼] [=] [月支 ▼]              [×]   │
└─────────────────────────────────────────────┘
含义：妻财爻.地支 与 月支 相同
例如：妻财爻是寅，月支也是寅，则匹配
```

**三合关系**（无顺序，无"于"字，需要3个地支）：
```
┌─────────────────────────────────────────────────────────────┐
│ [地支1 ▼] [地支2 ▼] [地支3 ▼] [三合] [X局 ▼]          [×]   │
└─────────────────────────────────────────────────────────────┘
```

含义：三个地支形成某三合局

X局选项：
- 木局（亥卯未）
- 火局（寅午戌）
- 金局（巳酉丑）
- 水局（申子辰）
- 不限（任意三合局）

**使用示例**：
- `[初爻] [三爻] [五爻] [三合] [水局]`：初爻、三爻、五爻形成申子辰三合水局
- `[月支] [日支] [年支] [三合] [不限]`：三支形成某三合局
- `[世爻] [应爻] [动爻] [三合] [木局]`：世爻、应爻、动爻形成亥卯未三合木局

### 4.6 关系对象列表

| 对象类型 | 可选项 | 说明 |
|---------|--------|------|
| **位置类** | 世爻、应爻、初爻~上爻 | 按爻位筛选 |
| **六亲类** | 父母爻、官鬼爻、子孙爻、妻财爻、兄弟爻 | 按本卦六亲筛选 |
| **六神类** | 青龙爻、朱雀爻、勾陈爻、螣蛇爻、白虎爻、玄武爻 | 按六神筛选 |
| **状态类** | 动爻、静爻、暗动爻 | 按爻状态筛选 |
| **伏神类** | 易冒伏神、增删伏神 | 按伏神筛选 |
| **飞神类** | 易冒飞神、增删飞神 | 按飞神筛选（需指定用神） |
| **条件组引用** | 条件组1的爻、条件组2的爻... | 引用已定义的条件组结果（自动命名） |
| **时间对象** | 年支、月支、日支 | 用于生旺墓绝参照 |

**三合关系特殊说明**：

三合关系与其他关系不同，需要选择3个地支对象，交互格式为：
```
[地支1 ▼] [地支2 ▼] [地支3 ▼] [三合] [X局 ▼]
```

使用三合关系时：
1. 需要依次选择3个地支来源对象
2. 第4个下拉选择三合局类型（木局/火局/金局/水局/不限）
3. 判断逻辑：三个地支是否形成指定的三合局

### 4.7 神煞字段设计

**核心概念**：神煞是**地支的神煞**，不是爻的神煞。判断某地支是否为/带某神煞。

**神煞列表**：

| 神煞 | 说明 |
|-----|------|
| 干禄 | 日干禄位 |
| 驿马 | 日支驿马位 |
| 羊刃 | 日干羊刃位 |
| 桃花 | 日支桃花位 |

**交互设计**（采用两步选择方式）：
```
┌─────────────────────────────────────────────┐
│ [某地支 ▼] [是/带/是或带 ▼] [干禄 ▼]   [×]   │
└─────────────────────────────────────────────┘

第一个下拉（地支来源）：
  - 爻对象：妻财爻、世爻、应爻、初爻~上爻...
  - 条件组引用：条件组1的爻、条件组2的爻...（自动命名）
  - 时间对象：年支、月支、日支
  - 伏神/飞神：易冒伏神、增删伏神、易冒飞神、增删飞神

第二个下拉（判断方式）：
  - 是：该地支本身就是某神煞所在的地支
  - 带：该地支与神煞地支有**相冲或相合**关系
  - 是或带：两者皆可

第三个下拉（神煞类型）：
  - 干禄、驿马、羊刃、桃花
```

**神煞爻对象选择**（作为关系对象使用时）：

当神煞爻作为关系对象（如"干禄爻"）出现在下拉选项中时，采用分两步选择的方式：
```
第一步：[神煞类型 ▼] → 选择干禄/驿马/羊刃/桃花
第二步：[是/带/是或带 ▼] → 选择判断方式
```

这样避免了列出12个选项（4种神煞 × 3种方式）过于冗长的问题。

**使用示例**：

| 需求 | 实现方式 |
|-----|---------|
| 妻财爻是干禄 | `[妻财爻] [是] [干禄]` |
| 月支带驿马 | `[月支] [带] [驿马]` |
| 条件组A的爻是或带桃花 | `[条件组A的爻] [是或带] [桃花]` |

**注意**：神煞判断与关系字段类似，都是对地支的判断，只是判断的内容不同：
- 关系字段：判断两个地支之间的关系
- 神煞字段：判断一个地支的神煞属性

// stores/useSearchStore.ts
import { defineStore } from 'pinia'
import { ref, computed } from 'vue'

export const useSearchStore = defineStore('search', () => {
  // ========== 状态 ==========

  /** 条件列表 */
  const conditions = ref<Condition[]>([])

  /** 逻辑链（AND/OR/括号） */
  const logicChain = ref<LogicItem[]>([])

  /** 检索结果 */
  const results = ref<SearchResult[]>([])

  /** 分页信息 */
  const pagination = ref({
    page: 1,
    pageSize: 20,
    total: 0
  })

  // ========== 计算属性 ==========

  /** 表达式预览 */
  const expressionPreview = computed(() => {
    return buildExpressionString(conditions.value, logicChain.value)
  })

  /** 是否有条件 */
  const hasConditions = computed(() => {
    return conditions.value.length > 0
  })

  // ========== 方法 ==========

  /** 添加条件 */
  function addCondition(condition: Condition) {
    const id = `cond_${Date.now()}`
    const parsed = parseField(condition.field) // 解析条件组字段

    conditions.value.push({
      ...condition,
      id,
      ...parsed
    })

    // 更新逻辑链
    if (conditions.value.length > 1) {
      logicChain.value.push({ type: 'operator', value: 'AND' })
    }
    logicChain.value.push({ type: 'condition', id })
  }

  /** 删除条件 */
  function removeCondition(id: string) {
    const index = conditions.value.findIndex(c => c.id === id)
    if (index !== -1) {
      conditions.value.splice(index, 1)
      rebuildLogicChain()
    }
  }

  /** 执行检索 */
  async function executeSearch() {
    const response = await fetch('/api/v3/search', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({
        conditions: conditions.value,
        logic: logicChain.value,
        pagination: pagination.value
      })
    })
    const data = await response.json()
    results.value = data.data.results
    pagination.value.total = data.data.total
  }

  /** 清空 */
  function clearAll() {
    conditions.value = []
    logicChain.value = []
    results.value = []
  }

  return {
    conditions,
    logicChain,
    results,
    pagination,
    expressionPreview,
    hasConditions,
    addCondition,
    removeCondition,
    executeSearch,
    clearAll
  }
})

### 7.2 SQL构建器

```python
# backend/services/search/sql_builder.py

class SearchQueryBuilder:
    def __init__(self):
        self.tables = {"g": "guali"}  # 基础表
        self.joins = set()
        self.where_conditions = []
        self.params = {}

    def build(self, conditions: List[Dict], logic: List[Dict]) -> tuple:
        """构建完整SQL"""

        condition_map = {c['id']: c for c in conditions}

        # 构建WHERE表达式
        where_expr = self._build_logic_expression(logic, condition_map)

        # 构建JOIN子句
        join_clause = self._build_joins()

        # 判断是否需要DISTINCT（有爻级条件时需要）
        need_distinct = any(
            FIELD_MAPPING.get(c['field'], {}).get('join') == 'guali_yao'
            for c in conditions
        )

        distinct = "DISTINCT" if need_distinct else ""

        sql = f"""
            SELECT {distinct} g.*
            FROM guali g
            {join_clause}
            WHERE {where_expr}
            ORDER BY g.zhanwen_time DESC
        """

        return sql, self.params

    def _build_condition_sql(self, condition: Dict) -> str:
        """构建单个条件的SQL"""

        field = condition['field']
        operator = condition['operator']
        value = condition['value']
        sources = condition.get('sources', ['本卦'])  # 默认本卦

        mapping = FIELD_MAPPING.get(field)
        if not mapping:
            raise ValueError(f"未知字段: {field}")

        # 记录需要的JOIN
        if mapping.get('join'):
            self.joins.add(mapping['join'])

        table = mapping['table']
        field_type = mapping['type']

        # 神煞类型特殊处理
        if field_type == 'shensha':
            return self._build_shensha_condition(condition, mapping)

        # 根据来源构建OR条件
        source_conditions = []
        for source in sources:
            column = mapping['column'].get(source, mapping['column']) \
                     if isinstance(mapping['column'], dict) \
                     else mapping['column']
            source_filter = FIELD_MAPPING['SOURCE_FILTERS'].get(source, '1=1')

            param_name = f"p_{condition['id']}_{source}"

            if operator == '=':
                sql = f"{table}.{column} = :{param_name}"
                self.params[param_name] = value

            elif operator == 'IN':
                placeholders = ', '.join([f":{param_name}_{i}" for i in range(len(value))])
                sql = f"{table}.{column} IN ({placeholders})"
                for i, v in enumerate(value):
                    self.params[f"{param_name}_{i}"] = v

            # 添加来源过滤
            if source_filter != '1=1':
                sql = f"({source_filter} AND {sql})"

            source_conditions.append(sql)

        # 多来源用OR连接
        if len(source_conditions) > 1:
            return f"({' OR '.join(source_conditions)})"
        return source_conditions[0]

    def _build_condition_group_sql(self, group: Dict) -> str:
        """构建条件组的SQL"""

        group_type = group['type']
        position = group.get('position')  # 爻位（同爻位条件组专用）
        sources = group.get('sources', [])
        conditions = group.get('conditions', [])

        if group_type == 'same_yao':
            # 同一爻条件组：OR逻辑
            source_conditions = []
            for source in sources:
                source_filter = FIELD_MAPPING['SOURCE_FILTERS'].get(source, '1=1')
                cond_list = []
                for cond in conditions:
                    sql = self._build_single_condition_sql(cond, source)
                    cond_list.append(sql)
                source_sql = ' AND '.join(cond_list)
                if source_filter != '1=1':
                    source_sql = f"({source_filter} AND {source_sql})"
                source_conditions.append(source_sql)
            return f"({' OR '.join(source_conditions)})"

        else:  # same_position
            # 同爻位条件组：AND逻辑
            source_conditions = []
            for source in sources:
                source_filter = FIELD_MAPPING['SOURCE_FILTERS'].get(source, '1=1')
                cond_list = []
                for cond in conditions:
                    sql = self._build_single_condition_sql(cond, source)
                    cond_list.append(sql)
                source_sql = ' AND '.join(cond_list)
                if source_filter != '1=1':
                    source_sql = f"({source_filter} AND {source_sql})"
                source_conditions.append(source_sql)
            # 添加爻位过滤
            position_filter = f"y.yao_position = {position}"
            all_conditions = [position_filter] + source_conditions
            return f"({' AND '.join(all_conditions)})"

    def _build_shensha_condition(self, condition: Dict, mapping: Dict) -> str:
        """构建神煞条件（是/带）"""

        shensha_name = mapping['shensha_name']
        value = condition['value']  # 如 ['是', '带']

        conditions = []
        if '是' in value:
            conditions.append(f"FIND_IN_SET(y.yao_position, s.ben_is_{shensha_name}) > 0")
        if '带' in value:
            conditions.append(f"FIND_IN_SET(y.yao_position, s.ben_dai_{shensha_name}) > 0")

        return f"({' OR '.join(conditions)})"
```

#### 【用户原始思路】（保留原话）

> 我们来一个个看第二章中的字段哪些是不够完备的
>
> 1. 时间类字段,这个没什么好说的,是完备的
>
> 2. 卦类字段,这个也不会涉及到有条件组的问题,比如要查找内卦爻变反吟且外卦伏吟的卦就直接能按卦例查找.很好找到(另:你那个2.2节的值来源没有写够,爻变反吟和伏吟也要区分内外卦)

>    3.1 比如我要查初爻为妻财且世爻为官鬼且世爻暗动的卦例,就不好查找,所以我们要分条件组

>
> 5. 伏神类字段和飞神类字段:对于同一爻条件组,我们一共有五个有爻存在的地方,分别是易冒伏神,增删伏神,本卦,变爻,之卦(静爻).所以对于同一爻条件组,我们要增加复选框,让用户自己选这个同一爻条件组的适用范围.
>    5.1 我们这里提出第二个条件组也就是同爻位条件组,这个条件组也是针对上面五个有爻存在的地方,也就是在这一个条件组内的条件都是针对于同一爻位上的爻的,但是这里的复选框就不能是简单一个横排了,需要分出来来代表不同的爻的检索区间
>    5.2 比如我们想要检索增删伏神的六亲的官鬼,且其飞神为世爻,且世爻是动爻,变爻六亲是妻财的卦例,那么我们就可以如下检索
>    ```
>    同爻位条件组
>    易冒伏神[不勾选]
>    增删伏神[勾选] 六亲=官鬼
>    本卦[勾选] 世应=世爻and爻状态=动爻
>    变爻[勾选] 六亲=妻财
>    之卦(静爻)[不勾选]
>    ```
>    5.3 按照这种方式就能筛选出来了.你有没有发现另一个好处,这样的话我们就能彻底摆脱符合字段而变成都是变成和2.3爻类字段一样的逻辑了
>
> 6. 同爻位条件组需要能和同一爻条件组嵌套使用
>
> 7. 我们相当于将整个爻类字段中的字段扩展到了增删伏神,易冒伏神和之卦中,只不过之卦需要根据爻类预存表中的是否动爻来确认哪个是变爻从而再分一次类
>
> 8. 所以爻类字段是不是还缺一个天干?我记得对于本卦和之卦预存表中都是有天干属性的
>

---

#### 【最终方案】两种条件组

##### 一、核心区别

| 条件组类型 | 核心约束 | 多选来源逻辑 | 本质 |
|-----------|---------|-------------|------|
| **同一爻条件组** | 同一**来源**的爻 | **OR**（满足任一来源即可） | 宽松匹配 |
| **同爻位条件组** | 同一**爻位** | **AND**（必须同一爻位） | 严格匹配 |

##### 二、五种爻来源

| 来源 | 说明 | 数据库字段前缀 |
|------|------|---------------|
| 本卦 | 本卦的6个爻 | `ben_*` |
| 变爻 | 动爻变化后的爻 | `zhi_*` + `is_dong=TRUE` |
| 之卦(静爻) | 之卦中未变化的爻 | `zhi_*` + `is_dong=FALSE` |
| 易冒伏神 | 每爻位的易冒伏神 | `yimao_*` |
| 增删伏神 | 有伏神的爻位 | `zengshan_*` |

##### 三、交互设计

**同一爻条件组**（多选来源 = OR）：
```
┌─────────────────────────────────────────────────────────┐
│ 同一爻条件组 【满足任一来源即可】                    [×]   │
│ ┌─────────────────────────────────────────────────────┐ │
│ │ 适用范围（可多选）:                                  │ │
│ │ ☑本卦 ☑增删伏神 ☐变爻 ☐之卦(静爻) ☐易冒伏神       │ │
│ ├─────────────────────────────────────────────────────┤ │
│ │ 条件:                                               │ │
│ │ [六亲] [=] [妻财] AND [地支] [=] [午]        [×]   │ │
│ └─────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────┘
```

**同爻位条件组**（同一爻位 = AND）：
```
┌─────────────────────────────────────────────────────────┐
│ 同爻位条件组 【必须同一爻位】                        [×]   │
│ ┌─────────────────────────────────────────────────────┐ │
│ │ ☐易冒伏神                                          │ │
│ │ ☑增删伏神    [六亲] [=] [官鬼]              [×]   │ │
│ │ ☑本卦        [世应] [=] [世爻] AND [暗动]=[是]     │ │
│ │ ☑变爻        [六亲] [=] [妻财]              [×]   │ │
│ │ ☐之卦(静爻)                                        │ │
│ └─────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────┘
```

##### 四、典型场景对比

**场景A**：查找"本卦或增删伏神中"有妻财午火的爻
```
使用：同一爻条件组
适用范围：☑本卦 ☑增删伏神
条件：六亲=妻财 AND 地支=午

结果：本卦第3爻满足（OR）增删伏神第5爻满足 → 都会返回
注意：本卦第3爻和增删伏神第5爻**不是同一爻位**！
```

**场景B**：查找"同一爻位上"增删伏神是官鬼，本卦是世爻的卦例
```
使用：同爻位条件组
☑增删伏神：六亲=官鬼
☑本卦：世应=世爻

结果：必须是**同一个爻位**（如第3爻），两个条件同时满足
```

##### 五、SQL生成逻辑

**同一爻条件组**（OR）：
```sql
SELECT DISTINCT g.*
FROM guali g
JOIN guali_yao y ON g.id = y.guali_id
WHERE (y.ben_liuqin = '妻财' AND y.ben_dizhi = '午')           -- 本卦
   OR (y.zengshan_liuqin = '妻财' AND y.zengshan_dizhi = '午'); -- 增删伏神
```

**同爻位条件组**（AND）：
```sql
SELECT DISTINCT g.*
FROM guali g
JOIN guali_yao y ON g.id = y.guali_id
WHERE y.zengshan_liuqin = '官鬼'   -- 增删伏神
  AND y.ben_shi_ying = '世'        -- 本卦（同一爻位）
  AND y.is_dong = TRUE             -- 有变爻
  AND y.zhi_liuqin = '妻财';       -- 变爻（同一爻位）
```

##### 六、结论

1. **需要保留两种条件组**，不能互相替代
2. **两者不需要嵌套**，语义互斥（OR vs AND）
3. **对于同爻位条件组,爻位只能在条件组外指定**，对于同一爻条件组,爻位可以在条件组内指定

### 【用户问】U3：关系类字段的本质——地支关系

**您的提问**：

关系类字段的使用，它会不会自动将两个东西之间的关系判定为它们之间**地支的关系**？

比如 `[妻财爻][生][世爻]` 严格来说是：
- **妻财爻的地支**的五行 来生 **世爻的地支**的五行

因为关系类处理的全是地支之间的关系，所以我认为：
1. **对于生克**：有严格的顺序来判断对象1的地支是生还是克对象2的地支（需要在运算时直接判断地支之间的生克）
2. **对于合冲和三合半合**：没有严格顺序，但也需要翻译成地支
3. **对于生旺墓绝**：也是有严格顺序的地支之间的关系

---

**我的回答**：

✅ **完全可以实现**，您的理解完全正确。

##### 核心原理

关系类字段**本质上处理的是地支之间的关系**，而不是爻本身的关系。

```
[妻财爻][生][世爻]
    ↓
妻财爻的地支（如巳-火） 生 世爻的地支（如未-土）
    ↓
火生土 → 成立
```

##### 实现方式

**第一步：确定地支**

每个"爻对象"都有对应的地支：

| 爻对象 | 地支来源 |
|-------|---------|
| 妻财爻 | 本卦中 `ben_liuqin='妻财'` 的爻的 `ben_dizhi` |
| 世爻 | 本卦中 `ben_shi_ying='世'` 的爻的 `ben_dizhi` |
| 变爻 | `is_dong=TRUE` 的爻的 `zhi_dizhi` |
| 月支 | `guali_time.month_zhi` |
| 易冒伏神 | `yimao_dizhi` |
| ... | ... |

**第二步：调用核心算法判断关系**

```python
def check_sheng(dizhi1, dizhi2):
    """判断地支1的五行是否生地支2的五行"""
    wuxing1 = get_wuxing(dizhi1)  # 如：巳→火
    wuxing2 = get_wuxing(dizhi2)  # 如：未→土
    return WUXING_SHENG[wuxing1] == wuxing2  # 火生土？

def check_ke(dizhi1, dizhi2):
    """判断地支1的五行是否克地支2的五行"""
    wuxing1 = get_wuxing(dizhi1)
    wuxing2 = get_wuxing(dizhi2)
    return WUXING_KE[wuxing1] == wuxing2

def check_he(dizhi1, dizhi2):
    """判断两个地支是否相合（无顺序）"""
    return (dizhi1, dizhi2) in LIUHE or (dizhi2, dizhi1) in LIUHE

def check_shengwang(dizhi1, dizhi2, relation):
    """判断地支1相对于地支2的生旺墓绝关系"""
    # 如：dizhi1=巳(火)，relation=长生，返回 dizhi2==寅？
    wuxing = get_wuxing(dizhi1)
    target = SHENGWANG_TABLE[wuxing][relation]  # 火的长生=寅
    return dizhi2 == target
```

##### 三类关系的顺序性

| 关系类型 | 顺序性 | 说明 |
|---------|-------|------|
| **生、克** | 有严格顺序 | A生B ≠ B生A；A克B ≠ B克A |
| **合、冲、三合、半合** | 无顺序 | A合B = B合A；A冲B = B冲A |
| **长生、帝旺、墓、绝** | 有严格顺序 | A长生于B ≠ B长生于A |

##### SQL生成示例

```sql
-- [妻财爻][生][世爻]
-- 有严格顺序：妻财爻的地支生世爻的地支
SELECT DISTINCT g.*
FROM guali g
JOIN guali_yao y1 ON g.id = y1.guali_id  -- 妻财爻
JOIN guali_yao y2 ON g.id = y2.guali_id  -- 世爻
WHERE y1.ben_liuqin = '妻财'
  AND y2.ben_shi_ying = '世'
  AND check_sheng(y1.ben_dizhi, y2.ben_dizhi) = TRUE;

-- [妻财爻][相合][世爻]
-- 无顺序：只需要判断两个地支是否相合
SELECT DISTINCT g.*
FROM guali g
JOIN guali_yao y1 ON g.id = y1.guali_id
JOIN guali_yao y2 ON g.id = y2.guali_id
WHERE y1.ben_liuqin = '妻财'
  AND y2.ben_shi_ying = '世'
  AND check_he(y1.ben_dizhi, y2.ben_dizhi) = TRUE;
  -- 内部实现：(y1地支,y2地支)或(y2地支,y1地支)在六合表中

-- [妻财爻][长生][于][月支]
-- 有严格顺序：妻财爻的地支长生于月支
SELECT DISTINCT g.*
FROM guali g
JOIN guali_yao y ON g.id = y.guali_id
JOIN guali_time t ON g.id = t.guali_id
WHERE y.ben_liuqin = '妻财'
  AND check_shengwang(y.ben_dizhi, t.month_zhi, '长生') = TRUE;
```
